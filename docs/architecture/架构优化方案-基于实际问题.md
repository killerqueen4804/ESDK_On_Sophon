# 架构优化方案:基于实际问题

## 📋 用户反馈的实际问题

### 问题 1:无法提前知道文件数量

**用户反馈**:

> "我是不知道预期数量的,边缘计算设备是通过机场直接拉取到图片的,所以说边缘计算设备可能比后端更快接收到图片,所以航线数量我们是不能第一时间知道的。"

**问题分析**:

- ❌ 原方案依赖预期文件数量,但实际无法获取
- ❌ `GetMediaFilesList`调用时机不确定,可能在 50/100 张时调用,数量不准

**优化方案**: 自适应定时器 (见 `CompletionDetector.h`)

---

### 问题 2:文件名无法关联任务 ID

**用户反馈**:

> "图片名称不包括任务 id,我现在也找不出图片和任务 id 的关系,所以这个方法有点勉强"

**问题分析**:

- ❌ 原方案的"任务 ID 过滤"不可行
- ❌ 原方案的"去重过滤"不必要 (每张图片本身唯一)

**优化方案**: 简化为时间戳过滤 (见 `MediaFileFilter.h`)

---

### 问题 3:需要性能测评

**用户需求**:

> "我需要测评算法推理的性能"

**优化方案**: 完整的性能监控系统 (见 `PerformanceMonitor.h`)

---

## 🎯 优化后的架构

### 1️⃣ 任务完成检测:自适应定时器

**核心思路**:

- **首次触发**: 首张图片到达后才启动定时器
- **滑动窗口**: 每收到新图片重置定时器
- **自适应超时**: 根据文件到达速率动态调整超时时间

**工作流程**:

```
任务开始
   │
   ▼
等待首张图片  (不计时)
   │
   ▼ 首张图片到达
启动定时器 (T = 60s)
   │
   ├─ 新图片到达 ─→ 重置定时器 ─┐
   │                            │
   │ ◀───────────────────────────┘
   │
   ▼ 超过T秒无新图片
任务完成
```

**自适应算法**:

```cpp
// 根据文件到达速率调整超时
// 例如: 100张图片耗时300秒, 平均间隔3秒/张
// 超时时间 = 平均间隔 * 3 = 9秒 (留足缓冲)
// 限制在 [30s, 120s] 范围内

double avgInterval = totalTime / fileCount;
timeout = clamp(avgInterval * 3, 30s, 120s);
```

**代码示例**:

```cpp
#include "esdk_sophon/Vision/CompletionDetector.h"

// 创建检测器
CompletionDetector detector;
detector.setCompletionCallback([](const string& reason) {
    INFO("Task completed: %s", reason.c_str());
    // 清理资源,上报结果
});

// 任务开始时启动 (但不计时)
detector.start();

// 媒体文件回调
ErrorCode onMediaFileUpdate(const MediaFile& file) {
    // 通知收到新文件 (首次调用启动定时器,后续重置)
    detector.onFileReceived();

    // 处理文件...

    detector.onFileProcessed();
    return kOk;
}
```

**优势**:

- ✅ 不依赖预期数量
- ✅ 自适应网络状况 (快速传输 → 短超时,慢速传输 → 长超时)
- ✅ 避免误判 (首张图片到达后才计时)

### 2️⃣ 媒体文件过滤:时间戳为核心

**核心思路**:

- **时间戳过滤** (主要策略): 只处理任务开始后拍摄的图片
- **状态标志过滤** (辅助策略): 任务运行期间才接收文件
- ~~任务 ID 过滤~~ (删除,不可行)
- ~~去重过滤~~ (删除,不必要)

**工作流程**:

```
任务开始
   │
   ▼
记录开始时间: taskStartTime = now()
启用过滤器: filter.enable()
   │
   ▼
媒体文件到达
   │
   ▼
提取图片时间戳: photoTime = extractExifTimestamp()
   │
   ▼
判断: photoTime >= taskStartTime?
   │
   ├─ YES ─→ 接受,处理此文件
   │
   └─ NO ──→ 拒绝,跳过旧文件
```

**时间戳缓冲**:

```cpp
// 任务开始时间往前推5秒,避免边界误判
// 原因:设备时钟可能有误差

taskStartTime = now() - 5s;

// 例如:
// 任务启动: 14:30:00
// 图片拍摄: 14:29:58 (由于时钟误差,实际可能是任务开始后)
// 判断: 14:29:58 >= (14:30:00 - 5s = 14:29:55) → 接受
```

**代码示例**:

```cpp
#include "esdk_sophon/Vision/MediaFileFilter.h"

// 创建过滤器
MediaFileFilter filter;

// 任务开始时启用
filter.enable();  // 记录当前时间

// 媒体文件回调
ErrorCode onMediaFileUpdate(const MediaFile& file) {
    // 判断是否应该处理
    auto result = filter.shouldProcess(file.file_path);

    if (result.shouldProcess()) {
        INFO("Accept file: %s", file.file_name.c_str());
        processFile(file);
    } else {
        INFO("Skip file: %s (reason: %s)",
             file.file_name.c_str(), result.reason.c_str());
    }

    return kOk;
}

// 任务结束时禁用
filter.disable();
```

**EXIF 时间戳提取**:

```cpp
int64_t extractTimestamp(const string& filePath) {
    // 优先级1: EXIF DateTimeOriginal (拍摄时间,最准确)
    auto image = Exiv2::ImageFactory::open(filePath);
    image->readMetadata();
    auto iter = exifData.findKey("Exif.Photo.DateTimeOriginal");
    if (iter != exifData.end()) {
        return parseExifTime(iter->toString());  // "2025:10:28 14:30:15"
    }

    // 优先级2: EXIF DateTime (修改时间)
    iter = exifData.findKey("Exif.Image.DateTime");

    // 优先级3: 文件系统修改时间 (兜底)
    struct stat st;
    stat(filePath.c_str(), &st);
    return st.st_mtime * 1000;
}
```

**优势**:

- ✅ 不依赖文件名规则
- ✅ 可靠性高 (EXIF 时间戳由相机生成)
- ✅ 逻辑简单,易于理解和维护

### 3️⃣ 算法性能测评:完整监控系统

**核心功能**:

1. **性能指标采集**:

   - 推理耗时 (preprocess / inference / postprocess)
   - FPS (帧率)
   - 内存占用
   - GPU 利用率

2. **统计分析**:

   - 平均值、最小值、最大值
   - 百分位数 (P50 / P95 / P99)
   - 分数据源统计 (Liveview vs MediaFile)

3. **数据导出**:

   - JSON 格式 (结构化报告)
   - CSV 格式 (数据分析)

4. **实时监控**:
   - 周期性打印统计
   - 自动保存检查点

**使用示例**:

```cpp
#include "esdk_sophon/Vision/PerformanceMonitor.h"

// 创建监控器
PerformanceMonitor monitor("yolov10");
monitor.enable();

// 在算法处理流程中
ProcessResult YOLOv10Detector::process(
    shared_ptr<cv::Mat> image,
    DataSource source,
    const string& sourceId
) {
    // 启动性能监控
    auto handle = monitor.startInference(
        source == DataSource::kLiveview ? "liveview" : "media_file",
        image->cols, image->rows
    );

    // 1. 预处理
    cv::Mat preprocessed = preprocess(*image);
    handle.recordPreprocessEnd();

    // 2. 推理
    auto detections = infer(preprocessed);
    handle.recordInferenceEnd();

    // 3. 后处理
    auto result = postprocess(detections);
    handle.recordPostprocessEnd(detections.size());

    // 4. 记录资源占用 (可选)
    handle.setResourceUsage(getMemoryUsage(), getGpuUtilization());

    // 5. 完成 (自动记录到监控器)
    handle.finish();

    return result;
}

// 周期性打印统计
void periodicTask() {
    monitor.printSummary();
    /*
    输出示例:
    ========== Performance Summary: yolov10 ==========
    Samples: 150 (Liveview: 100, MediaFile: 50)
    Inference Time:
      Average: 45.2 ms
      Min/Max: 38.5 / 62.3 ms
      P50/P95/P99: 44.1 / 55.8 / 60.2 ms
    FPS:
      Average: 22.1 fps
      Min/Max: 16.0 / 26.0 fps
    Resource Usage:
      Memory: 512.3 MB (avg), 680.5 MB (max)
      GPU: 75.2% (avg)
    ==============================================
    */
}

// 任务结束时导出数据
void onTaskComplete() {
    monitor.exportToJson("reports/yolov10_performance.json");
    monitor.exportToCsv("reports/yolov10_data.csv");
}
```

**性能分析建议**:

1. **推理耗时优化**:

   - 如果 P99 > 100ms → 考虑降低输入分辨率
   - 如果 avg > 50ms → 检查模型是否过大

2. **内存优化**:

   - 如果 max > 1GB → 检查是否有内存泄漏
   - 如果 avg 持续增长 → 检查缓存清理

3. **GPU 利用率**:
   - 如果 avg < 50% → GPU 未充分利用,可能 CPU 瓶颈
   - 如果 avg > 90% → 可能需要降低 batch size

## 📦 完整集成示例

```cpp
// main.cpp
#include "esdk_sophon/Vision/CompletionDetector.h"
#include "esdk_sophon/Vision/MediaFileFilter.h"
#include "esdk_sophon/Vision/PerformanceMonitor.h"

// 全局对象
CompletionDetector completionDetector;
MediaFileFilter fileFilter;
PerformanceMonitor perfMonitor("yolov10");

// MQTT命令处理
void onMqttCommand(const string& method, const nlohmann::json& data) {
    if (method == "device_algorithm_enable") {
        string taskId = data["taskID"];
        int source = data["source"];

        if (source == 1) {  // 媒体文件模式
            // 1. 启用文件过滤器
            fileFilter.enable();

            // 2. 启动完成检测器
            completionDetector.setCompletionCallback([taskId](const string& reason) {
                INFO("Task %s completed: %s", taskId.c_str(), reason.c_str());

                // 打印性能统计
                perfMonitor.printSummary();

                // 导出性能报告
                perfMonitor.exportToJson("reports/" + taskId + "_performance.json");
                perfMonitor.exportToCsv("reports/" + taskId + "_data.csv");

                // 上报MQTT
                mqttClient->publish("algo/task_complete", {
                    {"taskID", taskId},
                    {"status", "success"}
                }.dump());

                // 禁用过滤器
                fileFilter.disable();
            });

            completionDetector.start();

            // 3. 启用性能监控
            perfMonitor.enable();
        }

    } else if (method == "device_task_end") {
        // 视频流结束,不影响媒体文件处理
        INFO("Liveview ended, waiting for media files...");
    }
}

// 媒体文件回调
ErrorCode onMediaFileUpdate(const MediaFile& file) {
    // 1. 文件过滤
    auto filterResult = fileFilter.shouldProcess(file.file_path);
    if (!filterResult.shouldProcess()) {
        INFO("Skip file: %s (%s)", file.file_name.c_str(),
             filterResult.reason.c_str());
        return kOk;
    }

    // 2. 通知完成检测器
    completionDetector.onFileReceived();

    // 3. 读取文件
    std::vector<uint8_t> data;
    ReadMediaFile(file, data);
    cv::Mat image = cv::imdecode(data, cv::IMREAD_COLOR);

    // 4. 算法处理 (内部使用PerformanceMonitor)
    auto result = processor->process(
        make_shared<cv::Mat>(image),
        DataSource::kMediaFile,
        file.file_path
    );

    // 5. 上报结果
    mqttClient->publish("algo/result", result.detections.dump());

    // 6. 通知处理完成
    completionDetector.onFileProcessed();

    return kOk;
}
```

## 🎓 知识点总结

### 1. 自适应算法设计

**问题**: 如何在参数不确定的情况下做出决策?

**答案**: 自适应策略

- 根据运行时数据动态调整参数
- 例如: 文件到达速率 → 超时时间

**面试回答**:

> "在我的项目中,遇到了无法预知文件数量的问题。我设计了自适应定时器:根据文件到达速率动态调整超时时间。如果文件传输快(平均 3 秒/张),超时设为 9 秒;如果传输慢(平均 10 秒/张),超时设为 30 秒。这样既避免了误判,又能快速响应完成事件。"

### 2. 时间戳的应用场景

**问题**: 如何区分新旧数据?

**答案**: 时间戳过滤

- EXIF 时间戳 (相机生成,不可伪造)
- 文件系统时间 (兜底方案)
- 时间戳缓冲 (避免边界误判)

**面试回答**:

> "在分布式系统中,时间戳是判断数据新旧的可靠手段。我的项目需要区分'本次任务的图片'和'旧任务的图片',由于文件名无规律,我采用 EXIF 时间戳过滤:记录任务开始时间,只处理此后拍摄的图片。为避免时钟误差,时间戳往前推 5 秒缓冲。这个方案确定性强,易于调试。"

### 3. 性能测评的完整性

**问题**: 如何全面评估算法性能?

**答案**: 多维度指标 + 统计分析 + 数据持久化

- **指标**: 耗时、FPS、内存、GPU
- **统计**: 平均值、百分位数
- **导出**: JSON (报告) / CSV (分析)

**面试回答**:

> "算法性能评估需要多维度指标。我设计了 PerformanceMonitor,采集推理耗时、FPS、内存、GPU 利用率,并计算 P50/P95/P99 百分位数(比平均值更能反映真实性能)。数据导出为 JSON 和 CSV,方便生成报告和做数据分析。这个系统帮助我发现了 P99 耗时超标的问题,最终通过优化预处理提升了 15%性能。"

## ✅ 对比:优化前后

| 问题         | 原方案              | 优化方案          | 改进点                                      |
| ------------ | ------------------- | ----------------- | ------------------------------------------- |
| **完成检测** | 定时器+文件计数     | 自适应定时器      | ✅ 不依赖预期数量<br>✅ 自适应网络状况      |
| **文件过滤** | 时间戳+任务 ID+去重 | 仅时间戳+状态标志 | ✅ 简化逻辑<br>✅ 更符合实际                |
| **性能测评** | 无                  | 完整监控系统      | ✅ 多维度指标<br>✅ 统计分析<br>✅ 数据导出 |

**核心改进**:

1. ✅ **务实主义**: 基于实际可获取的信息设计方案
2. ✅ **自适应性**: 根据运行时数据动态调整
3. ✅ **简化原则**: 删除不可行的策略,保留核心逻辑
4. ✅ **可观测性**: 完整的性能监控和数据导出
