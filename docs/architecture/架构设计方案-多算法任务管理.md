# 架构设计方案:多算法任务管理

## 📋 问题总结

你提出的三个问题本质上是一个完整的**任务生命周期管理**问题:

1. **多算法模式灵活性**: 如何支持"视频流分析"、"图片推理"、"两者同时"、"变焦拍照"等多种组合?
2. **任务完成检测**: 如何判断"拿图片+推理"过程结束?定时器方案不够可靠。
3. **媒体文件管理**: 如何避免"多次任务图片混淆"?`SetDroneNestAutoDelete`效果不好。

## 🎯 核心设计思想

### 1️⃣ 分层架构

```
┌─────────────────────────────────────────────────────────────────┐
│  Main (任务编排层)                                               │
│  ─────────────────────────────────────────────────────────       │
│  接收MQTT指令 → 创建任务 → 分发数据 → 收集结果 → 上报         │
└──────────────────┬──────────────────────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────────────────────┐
│  TaskManager (任务管理层)                                        │
│  ─────────────────────────────────────────────────────────       │
│  1. 任务状态机 (Idle → Running → Ended → Processing → Complete) │
│  2. 完成检测 (定时器+文件计数+时间戳过滤)                       │
│  3. 媒体文件过滤 (只处理本次任务的图片)                         │
└──────────────────┬──────────────────────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────────────────────┐
│  AlgorithmProcessor (算法执行层)                                 │
│  ─────────────────────────────────────────────────────────       │
│  统一接口: process(cv::Mat, DataSource, sourceId)               │
│  策略模式: YOLOv10Detector | SegformerDetector | ...            │
└──────────────────┬──────────────────────────────────────────────┘
                   │
┌──────────────────┴──────────────────────────────────────────────┐
│  DeviceManager (数据采集层)                                      │
│  ─────────────────────────────────────────────────────────       │
│  统一输出: ImageCallback(shared_ptr<cv::Mat>)                   │
│  来源: Liveview (H264解码) | MediaFile (JPEG解码)               │
└─────────────────────────────────────────────────────────────────┘
```

### 2️⃣ 策略模式:多算法支持

**关键设计**:

- **统一接口**: `IAlgorithmProcessor::process(cv::Mat, DataSource, sourceId)`

  - 所有算法(YOLOv10, Segformer, 未来扩展)都实现此接口
  - `cv::Mat`统一数据格式,不关心来源
  - `DataSource`参数用于区分处理策略(快速推理 vs 高精度推理)

- **工厂创建**: `AlgorithmFactory::Create(algorithmName)`

  - 根据 MQTT 参数动态创建算法实例

- **模式配置**: `AlgorithmTaskConfig`
  - 从 MQTT 消息解析:`source=0`→ 仅视频流,`source=1`→ 仅图片,`source=2`→ 两者都要
  - 未来扩展:`source=3`→ 变焦拍照模式

**代码示例** (见 `AlgorithmTask.h`):

```cpp
enum class AlgorithmMode {
    kLiveviewOnly,      // 仅处理视频流
    kMediaFileOnly,     // 仅处理图片
    kBoth,              // 同时处理
    kZoomThenAnalyze    // 变焦拍照+推理 (未来)
};

// 统一的算法接口
class IAlgorithmProcessor {
    virtual ProcessResult process(
        std::shared_ptr<cv::Mat> image,
        DataSource source,  // 区分来源,采用不同策略
        const std::string& sourceId
    ) = 0;
};
```

**为什么需要`DataSource`参数?**

虽然输入都是`cv::Mat`,但不同来源需要不同处理:

```cpp
// YOLOv10Detector实现
ProcessResult YOLOv10Detector::process(
    std::shared_ptr<cv::Mat> image,
    DataSource source,
    const std::string& sourceId
) {
    if (source == DataSource::kLiveview) {
        // 实时流:优先速度,降低精度
        cv::resize(*image, resized, cv::Size(640, 640));
        auto result = fastInfer(resized);  // 快速推理

        // 生成可视化图片,用于RTMP推流
        result.visualizedImage = drawBoxes(resized, result.detections);

    } else if (source == DataSource::kMediaFile) {
        // 离线图片:优先精度,保持原分辨率
        auto result = highPrecisionInfer(*image);  // 高精度推理

        // 不需要可视化,节省计算

    } else if (source == DataSource::kZoomCapture) {
        // 变焦拍照:超高分辨率,特殊预处理
        auto result = preprocessAndInfer(*image);
    }

    result.source = source;
    result.sourceId = sourceId;
    return result;
}
```

### 3️⃣ 状态机:任务生命周期管理

**核心问题**: 如何判断"拿图片+推理"结束?

**旧方案的问题**:

- 纯定时器(60 秒无新图片):不可靠,可能误判
- 网络延迟、机场传输慢都会导致超时

**新方案:状态机+混合检测策略**

#### 任务状态机

```
     device_algorithm_enable (source=0)
              │
              ▼
      ┌───────────────┐
      │  Liveview     │  ← 视频流处理中
      │  Running      │     (实时推理+RTMP推流)
      └───────┬───────┘
              │ device_task_end (航线结束)
              ▼
      ┌───────────────┐
      │  Liveview     │
      │  Ended        │
      └───────┬───────┘
              │ 等待媒体文件
              ▼
      ┌───────────────┐
      │  MediaFile    │  ← 图片开始到达
      │  Processing   │     (批量推理)
      └───────┬───────┘
              │ 完成检测策略触发
              ▼
      ┌───────────────┐
      │  Completed    │  → 触发completeCallback
      └───────────────┘     清理资源,上报结果
```

#### 完成检测策略 (推荐:混合策略)

```cpp
enum class CompletionStrategy {
    kTimer,             // 60秒无新文件 → 完成
    kFileCount,         // 处理数量==预期数量 → 完成
    kTimerPlusCount,    // 两者都满足 → 完成 (推荐!)
    kExplicitSignal     // 未来:MQTT发送完成信号
};

bool TaskManager::checkTaskCompletion(const std::string& taskId) {
    auto& state = tasks_[taskId];

    switch (state.completionStrategy) {
    case CompletionStrategy::kTimerPlusCount:
        // 混合策略:
        // 1. 超过60秒无新文件 (避免卡死)
        // 2. 且已处理数量>0 (避免一张没收到就超时)
        auto elapsed = now() - state.lastMediaFileTime;
        bool timerOk = (elapsed > 60s && state.mediaFilesProcessed > 0);

        // 如果知道预期数量,检查是否全部完成
        bool countOk = (state.expectedMediaFiles > 0 &&
                       state.mediaFilesProcessed >= state.expectedMediaFiles);

        if (timerOk || countOk) {
            completeTask(taskId, true);
            return true;
        }
        break;
    }
    return false;
}
```

### 4️⃣ 媒体文件过滤:解决"图片一股脑传过来"

**核心问题**: 机场存储了多次任务的图片,启用算法后全部传输,导致推理了旧任务的图片。

**旧方案的问题**:

```cpp
SetDroneNestAutoDelete(false);  // 处理前关闭自动删除
// ... 处理
SetDroneNestAutoDelete(true);   // 处理后打开自动删除
// 问题:不可靠,时序不确定,可能删除了正在传输的文件
```

**新方案:时间戳过滤+任务 ID 过滤**

```cpp
bool TaskManager::shouldProcessMediaFile(
    const std::string& taskId,
    const std::string& fileId,
    int64_t fileTimestamp  // 从EXIF提取
) {
    auto& state = tasks_[taskId];

    // 策略1:时间戳过滤 (核心!)
    // 只处理taskStartTime之后拍摄的图片
    if (fileTimestamp < toMillis(state.taskStartTimestamp)) {
        INFO("Skip old file (before task start): %s", fileId.c_str());
        return false;  // 这是旧任务的图片,跳过!
    }

    // 策略2:任务ID过滤 (如果文件名包含taskID)
    // 例如: "DJI_20251027_task001_IMG_0015.JPEG"
    if (fileId.find(taskId) == std::string::npos) {
        INFO("Skip file from different task: %s", fileId.c_str());
        return false;
    }

    // 策略3:去重过滤
    if (std::find(state.receivedFileIds.begin(),
                  state.receivedFileIds.end(),
                  fileId) != state.receivedFileIds.end()) {
        INFO("Skip duplicate file: %s", fileId.c_str());
        return false;
    }

    // 通过所有检查,处理此文件
    state.receivedFileIds.push_back(fileId);
    state.lastMediaFileTime = std::chrono::steady_clock::now();
    return true;
}
```

**如何提取 EXIF 时间戳?**

```cpp
#include <exiv2/exiv2.hpp>

int64_t extractExifTimestamp(const std::string& filePath) {
    try {
        auto image = Exiv2::ImageFactory::open(filePath);
        image->readMetadata();

        auto& exifData = image->exifData();

        // 提取拍摄时间
        auto iter = exifData.findKey(Exiv2::ExifKey("Exif.Photo.DateTimeOriginal"));
        if (iter != exifData.end()) {
            std::string timeStr = iter->toString();
            // 解析为时间戳 (格式: "2025:10:27 14:30:15")
            return parseExifTime(timeStr);
        }
    } catch (const std::exception& e) {
        ERROR("Extract EXIF failed: %s", e.what());
    }

    // 如果EXIF失败,使用文件修改时间
    struct stat st;
    stat(filePath.c_str(), &st);
    return st.st_mtime * 1000;  // 转为毫秒
}
```

**完整流程**:

```cpp
// MediaFilesObserver回调
ErrorCode MediaFilesUpdateCallback(const MediaFile& file) {
    // 1. 提取文件时间戳
    int64_t timestamp = extractExifTimestamp(file.file_path);

    // 2. 询问TaskManager是否应该处理
    if (TaskManager::Instance().shouldProcessMediaFile(
            currentTaskId, file.file_path, timestamp)) {

        // 3. 通知收到新文件
        TaskManager::Instance().onMediaFileReceived(
            currentTaskId, file.file_path, timestamp);

        // 4. 加入处理队列
        media_file_queue.push(file);
        media_file_queue_cv.notify_one();

    } else {
        INFO("Skip file: %s (old task or duplicate)", file.file_name.c_str());
    }

    return kOk;
}

// 处理线程
void ProcessMediaFileThread() {
    while (true) {
        MediaFile file = media_file_queue.pop();

        // 读取并解码
        std::vector<uint8_t> data;
        ReadMediaFile(file, data);
        cv::Mat image = cv::imdecode(data, cv::IMREAD_COLOR);

        // 调用算法处理
        auto result = processor->process(
            std::make_shared<cv::Mat>(image),
            DataSource::kMediaFile,
            file.file_path
        );

        // 通知处理完成
        TaskManager::Instance().onMediaFileProcessed(
            currentTaskId, file.file_path);

        // 检查是否全部完成
        if (TaskManager::Instance().checkTaskCompletion(currentTaskId)) {
            INFO("Task %s completed!", currentTaskId.c_str());
            break;
        }
    }
}
```

### 5️⃣ 未来扩展:变焦拍照+推理

**场景**: 实时视频流检测到目标 → 控制云台变焦 → 拍摄高分辨率照片 → 对照片做精细推理

**架构支持**:

```cpp
// 新增数据源类型
enum class DataSource {
    kLiveview,
    kMediaFile,
    kZoomCapture  // 变焦拍照
};

// 新增算法模式
enum class AlgorithmMode {
    kLiveviewOnly,
    kMediaFileOnly,
    kBoth,
    kZoomThenAnalyze  // 变焦拍照模式
};

// 处理流程
ProcessResult YOLOv10Detector::process(cv::Mat image, DataSource source, ...) {
    if (source == DataSource::kLiveview && mode == kZoomThenAnalyze) {
        // 1. 快速检测
        auto detections = fastInfer(image);

        // 2. 如果检测到关键目标,触发拍照
        if (hasKeyTarget(detections)) {
            // 通过DeviceManager控制云台
            deviceMgr->controlGimbal(zoomLevel, targetPos);
            deviceMgr->triggerCapture();
            // 后续收到kZoomCapture类型的图片,做精细推理
        }

    } else if (source == DataSource::kZoomCapture) {
        // 3. 高分辨率精细推理
        auto detailedResult = highPrecisionInfer(image);
        return detailedResult;
    }
}
```

## 📦 完整代码示例

### Main 程序编排

```cpp
// src/main.cpp
#include "esdk_sophon/Vision/TaskManager.h"
#include "esdk_sophon/Vision/AlgorithmTask.h"
#include "esdk_sophon/Device/DeviceManager.h"
#include "esdk_sophon/Mqtt/MqttClient.h"

using namespace esdk_sophon;

// 全局变量
std::shared_ptr<vision::IAlgorithmProcessor> currentProcessor;
std::string currentTaskId;

// MQTT命令处理
void onMqttCommand(const std::string& method, const nlohmann::json& data) {
    if (method == "device_algorithm_enable") {
        // 1. 解析配置
        auto config = vision::AlgorithmTaskConfig::FromMqttMessage(data);
        currentTaskId = config.taskId;

        // 2. 设置结果回调
        config.resultCallback = [](const vision::ProcessResult& result) {
            if (result.source == vision::DataSource::kLiveview) {
                // 实时流结果:推送RTMP
                rtmpStreamer->pushFrame(result.visualizedImage);
            } else if (result.source == vision::DataSource::kMediaFile) {
                // 图片结果:上报MQTT
                mqttClient->publish("algo/result", result.detections.dump());
            }
        };

        // 3. 设置完成回调
        config.completeCallback = [](const std::string& taskId, int total, bool success) {
            INFO("Task %s completed! Processed %d images/frames",
                 taskId.c_str(), total);

            // 上报最终统计
            nlohmann::json summary = {
                {"taskID", taskId},
                {"total_processed", total},
                {"status", success ? "success" : "failed"}
            };
            mqttClient->publish("algo/task_complete", summary.dump());

            // 清理资源
            currentProcessor->release();
            currentProcessor.reset();
        };

        // 4. 创建算法处理器
        currentProcessor = vision::AlgorithmFactory::Create(config.algorithmName);
        currentProcessor->initialize(config);

        // 5. 启动任务
        vision::TaskManager::Instance().startTask(config);

        // 6. 根据模式启动数据源
        if (config.enableLiveview) {
            device::DeviceManager::Instance().startLiveview(
                [](std::shared_ptr<cv::Mat> image) {
                    // 统一的图像回调
                    auto result = currentProcessor->process(
                        image,
                        vision::DataSource::kLiveview,
                        "liveview_stream"
                    );

                    // 触发结果回调
                    if (result.callback) {
                        result.callback(result);
                    }

                    // 更新统计
                    // ...
                }
            );
        }

        if (config.enableMediaFile) {
            device::DeviceManager::Instance().enableMediaFileProcessing(true);
        }

    } else if (method == "device_task_end") {
        // 通知视频流结束
        vision::TaskManager::Instance().onLiveviewEnded(currentTaskId);

        // 停止视频流
        device::DeviceManager::Instance().stopLiveview();
    }
}

// 媒体文件回调
ErrorCode onMediaFileUpdate(const MediaFile& file) {
    // 1. 提取时间戳
    int64_t timestamp = extractExifTimestamp(file.file_path);

    // 2. 询问是否应该处理
    if (!vision::TaskManager::Instance().shouldProcessMediaFile(
            currentTaskId, file.file_path, timestamp)) {
        return kOk;  // 跳过旧文件
    }

    // 3. 通知收到新文件
    vision::TaskManager::Instance().onMediaFileReceived(
        currentTaskId, file.file_path, timestamp);

    // 4. 读取并处理
    std::vector<uint8_t> data;
    ReadMediaFile(file, data);
    cv::Mat image = cv::imdecode(data, cv::IMREAD_COLOR);

    auto result = currentProcessor->process(
        std::make_shared<cv::Mat>(image),
        vision::DataSource::kMediaFile,
        file.file_path
    );

    // 5. 通知处理完成
    vision::TaskManager::Instance().onMediaFileProcessed(
        currentTaskId, file.file_path);

    // 6. 检查是否全部完成
    vision::TaskManager::Instance().checkTaskCompletion(currentTaskId);

    return kOk;
}

int main() {
    // 初始化MQTT
    mqttClient->connect(...);
    mqttClient->subscribe("algo/command", onMqttCommand);

    // 初始化设备
    device::DeviceManager::Instance().initialize();
    device::DeviceManager::Instance().registerMediaFileObserver(onMediaFileUpdate);

    // 运行
    while (true) {
        std::this_thread::sleep_for(std::chrono::seconds(1));
    }

    return 0;
}
```

## 🎓 面试考点总结

### 1. 设计模式应用

**Q: 这个架构用了哪些设计模式?**

A:

- **策略模式**: `IAlgorithmProcessor`接口,不同算法(YOLOv10, Segformer)是不同策略
- **工厂模式**: `AlgorithmFactory::Create()`根据名称创建算法实例
- **观察者模式**: `MediaFilesObserver`、`IDeviceObserver`用于事件通知
- **单例模式**: `TaskManager`、`DeviceManager`全局唯一
- **状态模式**: `TaskState`状态机管理任务生命周期

### 2. 并发控制

**Q: 如何保证线程安全?**

A:

- **任务状态表**: `std::map<taskId, TaskRuntimeState>`用`std::mutex`保护
- **媒体文件队列**: `std::queue`+`std::mutex`+`std::condition_variable`
- **原子标志**: `std::atomic<bool> killer`用于线程间通信

### 3. 异步完成检测

**Q: 如何判断异步任务完成?**

A: **混合策略**:

- **定时器**: 60 秒无新数据 (避免卡死)
- **计数器**: 处理数量==预期数量 (精确判断)
- **时间戳**: 只处理任务开始后的文件 (过滤旧数据)

### 4. 扩展性设计

**Q: 如何支持未来的"变焦拍照"功能?**

A:

- **枚举扩展**: `DataSource::kZoomCapture`、`AlgorithmMode::kZoomThenAnalyze`
- **接口不变**: `process(cv::Mat, DataSource, sourceId)`接口支持新类型
- **策略分发**: 根据`DataSource`采用不同处理策略

## ✅ 总结

| 问题             | 旧方案         | 新方案              | 优势              |
| ---------------- | -------------- | ------------------- | ----------------- |
| **多算法模式**   | 硬编码 if-else | 策略模式+配置驱动   | 易扩展,易测试     |
| **完成检测**     | 60 秒定时器    | 状态机+混合策略     | 更可靠,更精确     |
| **媒体文件过滤** | SetAutoDelete  | 时间戳+任务 ID 过滤 | 无副作用,确定性强 |

**核心改进**:

1. ✅ **分离关注点**: 任务管理、算法执行、数据采集分层
2. ✅ **统一接口**: `process(cv::Mat, DataSource)`适配所有场景
3. ✅ **状态驱动**: 清晰的状态机替代隐式逻辑
4. ✅ **主动过滤**: 时间戳判断替代被动删除
5. ✅ **易于扩展**: 新增算法/模式只需实现接口
