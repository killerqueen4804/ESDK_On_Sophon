**优势**: 增量编译快、依赖清晰、易测试、可复用

## 🌟 重要决策记录

### 决策 1: 每个模块都有独立的 CMakeLists.txt

**学习者最初想法**: "文件不多，一个 CMakeLists.txt 就够了"

**导师反驳理由**:

1. ✅ 增量编译：修改 mqtt 只重新编译 libmqtt.a（3 秒 vs 30 秒）
2. ✅ 依赖清晰：每个模块明确声明依赖
3. ✅ 单元测试：可以单独测试每个模块
4. ✅ 代码复用：模块可作为独立库使用
5. ✅ 团队协作：避免 Git 冲突
6. ✅ 工业标准：OpenCV、TensorFlow 都这样做

**最终结果**: 学习者选择 A 听从建议 ✅

### 决策 2: vision 拆分为 3 个子模块

- detector：目标检测（YOLOv10）
- segmentation：图像分割（PaddleSeg）
- stream：视频流处理（FFmpeg/GStreamer）

**理由**: 职责不同、依赖不同、独立演进、可选裁剪

### 决策 3: utils 不依赖 core

**理由**: 避免循环依赖、最大化复用、清晰的层次

## 💡 CMake 核心概念

### PUBLIC vs PRIVATE vs INTERFACE

```cmake
# PUBLIC：当前需要 + 传递给依赖者
target_link_libraries(mqtt PUBLIC core)

# PRIVATE：只有当前需要
target_link_libraries(mqtt PRIVATE ThirdParty::Qt5Mqtt)

# INTERFACE：当前不需要 + 传递给依赖者
add_library(vision INTERFACE)
target_link_libraries(vision INTERFACE detector segmentation stream)
```

### 静态库 vs 动态库

**本项目选择 STATIC**:

- 嵌入式设备，简化部署
- 不需要多程序共享
- 避免动态库版本冲突

##🎓 面试要点

### 高频问题

**Q1: target_link_libraries 的 PUBLIC 和 PRIVATE 有什么区别？**

A:

- PUBLIC：依赖库的类型出现在公共接口中
- PRIVATE：依赖库只在内部实现中使用

例子：

```cpp
// MqttClient.h（公共接口）
class MqttClient {
public:
    void setLogger(core::Logger* logger);  // core类型 → PUBLIC
private:
    QMqttClient* client_;  // Qt类型只在内部 → PRIVATE
};
```

**Q2: 如何避免循环依赖？**

A:

1. 依赖倒置原则（DIP）：依赖抽象而非具体类
2. 分层架构：明确依赖方向（只能上层依赖下层）
3. 接口隔离：使用回调、观察者模式解耦
4. 提取公共部分：将双方依赖的部分提到更底层

**Q3: C++11 的单例为什么是线程安全的？**

A: C++11 标准规定，静态局部变量的初始化是线程安全的。编译器会在第一次调用时加锁，确保只初始化一次。（Meyers Singleton）

**Q4: 什么是 Pimpl 惯用法？有什么优势？**

A: Pointer to Implementation，将实现细节放在单独的类中，头文件只包含指向该类的指针。
优势：

1. 隐藏实现细节
2. 减少编译依赖
3. 加快编译速度
4. 保持 ABI 稳定

## 📝 项目讲述模板（面试用）

**背景**:
这是一个 DJI 无人机边缘计算项目，我负责将旧项目重构为现代化的 C++17 项目。

**挑战**:
原项目代码耦合严重、第三方库管理混乱、没有模块化设计。

**方案**:

1. 采用分层架构：utils→core→ 业务模块 →main
2. 头文件分离：include/公共接口 + src/内部实现
3. CMake 模块化：每个模块独立 CMakeLists.txt，使用 IMPORTED 和 STATIC 库
4. 设计模式：单例(Logger)、工厂+策略(detector)、Repository(storage)

**技术亮点**:

- 使用 C++11 Meyers Singleton 实现线程安全的单例
- 使用 Pimpl 减少编译依赖，加快编译速度
- 使用 PUBLIC/PRIVATE 精确控制依赖传递
- 使用 INTERFACE 库组合子模块

**成果**:

- 增量编译时间从 30 秒降至 3 秒
- 模块间依赖关系清晰，避免了循环依赖
- 代码可维护性和可扩展性大幅提升
- 建立了符合工业标准的项目结构

**收获**:
深入理解了 CMake 构建系统、设计模式、SOLID 原则，以及如何进行大型项目的架构设计。
