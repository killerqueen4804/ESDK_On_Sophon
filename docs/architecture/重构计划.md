## 🔑 关键设计原则详解

### 1️⃣ SOLID 原则 (面试必考！)

#### S - 单一职责原则 (Single Responsibility Principle)

**定义**: 一个类应该只有一个引起它变化的原因

**旧代码问题示例**:

```cpp
// ❌ 错误：一个类做了太多事情
class MqttClient {
    void connect();
    void subscribe();
    void processMessage();      // MQTT功能
    void saveToDatabase();      // 数据库功能
    void runYoloDetection();   // 视觉处理功能
    void controlDrone();       // 设备控制功能
};
```

**重构后**:

```cpp
// ✅ 正确：每个类只负责一件事
class MqttClient {
    void connect();
    void subscribe();
    void publish();
};

class MessageProcessor {
    void processMessage(const Message& msg);
};

class VisionDetector {
    void detect(const cv::Mat& image);
};
```

#### O - 开闭原则 (Open-Closed Principle)

**定义**: 对扩展开放，对修改关闭

**实现方式**: 使用接口和多态

```cpp
// ✅ 定义检测器接口
class IDetector {
public:
    virtual ~IDetector() = default;
    virtual DetectionResult detect(const cv::Mat& image) = 0;
};

// 扩展新的检测器时，不需要修改已有代码
class Yolov10Detector : public IDetector {
public:
    DetectionResult detect(const cv::Mat& image) override;
};

class Yolov8Detector : public IDetector {
public:
    DetectionResult detect(const cv::Mat& image) override;
};
```

#### L - 里氏替换原则 (Liskov Substitution Principle)

**定义**: 子类必须能够替换父类

#### I - 接口隔离原则 (Interface Segregation Principle)

**定义**: 不应强迫客户端依赖它们不使用的接口

#### D - 依赖倒置原则 (Dependency Inversion Principle)

**定义**: 高层模块不应依赖低层模块，都应依赖抽象
