## 问题回顾

### 死锁现象

程序在启动时卡死:

```bash
======================================
  Detector模块单元测试
======================================
# ← 卡死在这里,无任何输出
```

### 死锁原因

**循环依赖导致的静态初始化死锁**:

```cpp
// 错误的初始化顺序
main() → config.load()
  → Config::Impl::load() [持有mutex锁]
    → Logger::getInstance().info() [第一次调用Logger]
      → Logger::Logger() [构造函数]
        → pImpl_->loadConfigSettings()
          → Config::getInstance() [尝试获取Config]
            💥 等待mutex锁释放 → 死锁!
```

**核心问题**:

1. Config::load() 持有互斥锁
2. Config 在加载时调用 Logger 记录日志
3. Logger 构造时尝试读取 Config 配置
4. 两者互相等待 → 死锁

---

## 解决方案

### 修复代码

**test_detector.cpp main() 函数**:

```cpp
int main() {
    std::cout << "======================================" << std::endl;
    std::cout << "  Detector模块单元测试" << std::endl;
    std::cout << "======================================" << std::endl;

    // 🔧 修复死锁: 先初始化Logger(使用默认配置),再加载Config
    // 原因: Config.load()会调用Logger, 而Logger构造时会读Config, 造成循环依赖
    auto& logger = esdk_sophon::core::Logger::getInstance();
    std::cout << "✅ Logger已初始化(使用默认配置)" << std::endl;

    // ✅ 加载配置文件 (VisionConfigLoader需要)
    auto& config = esdk_sophon::core::Config::getInstance();
    std::string configPath = "../config/config.json";

    if (config.load(configPath)) {
        std::cout << "✅ 配置文件加载成功: " << configPath << std::endl;
    } else {
        std::cout << "⚠️  配置文件加载失败: " << configPath << std::endl;
        std::cout << "   test9将使用fallback配置" << std::endl;
    }
    std::cout << std::endl;

    // 运行所有测试...
}
```

### 原理分析

**安全的初始化顺序**:

```
1. Logger::getInstance()
   ↓
   Logger::Logger() 构造
   ↓
   loadConfigSettings()
   ↓
   Config::getInstance() [Config未加载,返回默认值,安全!]
   ↓
   ✅ Logger初始化完成(使用默认配置)

2. Config::load()
   ↓
   Logger::getInstance().info() [Logger已初始化,直接使用]
   ↓
   加载JSON配置
   ↓
   ✅ Config加载完成
```

**关键点**:

- ✅ Logger 先初始化,使用默认配置
- ✅ Config 后加载,可以安全使用 Logger
- ✅ 打破循环依赖,避免死锁

## 技术收获

### 1. 单例模式陷阱

**Meyers' Singleton 不是万能的**:

- C++11 保证线程安全的初始化
- 但不能解决循环依赖问题
- 两个单例互相引用 → 死锁风险

### 2. 静态初始化顺序

**关键原则**:

```cpp
// ❌ 错误: 隐式初始化顺序
Config::load();  // 内部调用 Logger

// ✅ 正确: 显式控制顺序
Logger::getInstance();  // 先初始化不依赖的
Config::load();         // 再初始化依赖的
```

### 3. 依赖关系设计

**好的依赖结构**:

```
Application
    ↓
 Config (依赖)
    ↓
 Logger (底层,不依赖其他)
```

**坏的依赖结构**:

```
Config ⇄ Logger  (循环依赖,危险!)
```

### 4. 调试技巧

**死锁诊断步骤**:

1. 观察症状: 卡死,无输出,CPU 占用低
2. gdb backtrace: 查看调用栈
3. 追踪单例构造顺序
4. 绘制依赖图,查找环
5. 控制初始化顺序或解除依赖
