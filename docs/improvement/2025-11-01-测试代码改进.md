## 🎯 面试要点

### Q1: 为什么不用 `passed &=` 来累积测试结果?

**A**:

```
问题:
1. 不可恢复 - 一次失败后,所有后续测试都显示失败
2. 难以定位 - 无法知道是哪一个子测试失败
3. 误导性强 - 后续测试可能是成功的,但显示为失败

正确做法:
1. 独立判断 - 每个测试用独立变量存储结果
2. 计数统计 - 用 passCount/totalTests 显示通过率
3. 清晰诊断 - 输出每个子测试的具体结果

示例:
// 错误
bool passed = true;
passed &= (a == 1);  // 失败
passed &= (b == 2);  // 实际成功,但passed已经是false

// 正确
int pass = 0, total = 0;
total++; if (a == 1) pass++;  // 失败, pass=0/1
total++; if (b == 2) pass++;  // 成功, pass=1/2
std::cout << "通过率: " << pass << "/" << total << std::endl;  // 1/2
```

### Q2: 如何测试未初始化状态下的接口行为?

**A**:

```cpp
测试目标: 验证接口的鲁棒性和默认行为

1. 明确标注测试意图
   @note 不调用initialize(),测试默认行为

2. 定义合理的预期行为
   - 返回类型相关:
     * string → 返回固定字符串或空串
     * int → 返回0或-1
     * Size → 返回(0,0)或合理默认值
   - 状态查询:
     * isInitialized() → false
     * hasData() → false

3. 提供诊断和建议
   if (unexpected_value) {
       std::cout << "建议: 在构造函数初始化默认值" << std::endl;
   }

示例:
cv::Size size = detector.getInputSize();
bool test = (size.width == 0) ||           // 方案A: 返回0表示未初始化
            (size.width == 640);           // 方案B: 返回默认尺寸
// 两种都是合理的设计
```

## 🐛 第三轮改进: 修复 Config 未加载问题 (2025-11-01)

### 问题发现

用户运行 test9 后发现:

```
[WARN] 未配置检测器模型路径: detector.ppyoloe.model_path
[WARN] 将使用空路径,初始化时可能失败
✅ 从config.json加载配置成功:
   模型路径:          <-- ❌ 空的!
   配置文件:          <-- ❌ 空的!
```

**问题根源**:

1. VisionConfigLoader 使用 `Config::getInstance()` 读取配置
2. Config 单例**不会自动加载配置文件**,需要手动调用 `load()`
3. 测试代码中**没有加载 config.json**
4. 所以 Config 是空的,返回所有默认值

**问题影响**:

- ❌ VisionConfigLoader 读取不到配置,返回空字符串
- ❌ createTestConfig() 的 try 块成功执行,但得到空配置
- ❌ catch 块的 fallback 路径没有被使用
- ❌ 检测器初始化失败: "模型文件不存在: "

### 根本原因分析

#### Config 单例的设计

```cpp
// Config.cpp
Config& Config::getInstance() {
    static Config instance;  // Meyers' Singleton
    return instance;
}

Config::Config()
    : pImpl_(std::make_unique<Impl>())  // 只创建Impl,不加载配置
{
}

bool Config::load(const std::string& configPath) {
    return pImpl_->load(configPath);  // ⭐ 需要手动调用
}
```

**设计特点**:

- ✅ 延迟加载: 允许用户选择配置文件路径
- ✅ 灵活性: 可以 reload() 切换配置

### 知识点总结

#### 单例模式的初始化策略

**1. 饿汉式 (Eager Initialization)**

```cpp
class Config {
public:
    static Config& getInstance() {
        return instance_;
    }
private:
    Config() {
        load("default.json");  // 自动加载
    }
    static Config instance_;  // 静态实例,程序启动时初始化
};
```

- **优点**: 线程安全,自动初始化
- **缺点**: 浪费资源(即使不用也会初始化)

**2. 懒汉式 + 手动加载 (Lazy + Manual Load)** ⭐ 当前方案

```cpp
class Config {
public:
    static Config& getInstance() {
        static Config instance;  // 第一次调用时初始化
        return instance;
    }

    bool load(const std::string& path) {
        // 需要用户手动调用
    }
};
```

- **优点**: 延迟加载,灵活选择配置文件
- **缺点**: 需要记得调用 load()

**3. 懒汉式 + 自动加载 (Lazy + Auto Load)**

```cpp
class Config {
public:
    static Config& getInstance() {
        static Config instance("default.json");  // 自动加载默认配置
        return instance;
    }
private:
    Config(const std::string& path) {
        load(path);
    }
};
```

- **优点**: 延迟加载 + 自动初始化
- **缺点**: 配置路径硬编码

#### 面试要点

**Q1: 为什么 Config 不自动加载配置文件?**

**A**:

```
设计权衡:
1. 灵活性 - 允许运行时指定配置文件路径
   - 开发环境: "config/dev.json"
   - 测试环境: "config/test.json"
   - 生产环境: "/etc/esdk/config.json"

2. 可测试性 - 单元测试可以使用不同配置
   config.load("test_config.json");

3. 错误处理 - 用户可以检查 load() 返回值
   if (!config.load(path)) {
       fallback();
   }

缺点:
- 容易忘记调用 load()
- 需要在多处调用点检查是否已加载

改进方案:
- 添加 isLoaded() 检查方法
- VisionConfigLoader 构造时检查并提示
```

**Q2: 如何设计一个健壮的配置管理系统?**

**A**:

```cpp
class Config {
public:
    // 1. 检查是否已加载
    bool isLoaded() const {
        return pImpl_->configLoaded_;
    }

    // 2. 安全的读取方法(检查加载状态)
    std::string getStringSafe(const std::string& key) const {
        if (!isLoaded()) {
            throw std::runtime_error("Config not loaded");
        }
        return getString(key, "");
    }

    // 3. 配置验证
    bool validate() const {
        // 检查必需配置项是否存在
        if (!has("detector.ppyoloe.model_path")) {
            return false;
        }
        return true;
    }

    // 4. 配置热重载
    bool reload() {
        return pImpl_->reload();
    }
};

// 使用者负责检查
auto& config = Config::getInstance();
if (!config.isLoaded()) {
    config.load("default.json");
}
if (!config.validate()) {
    throw std::runtime_error("Invalid config");
}
```
