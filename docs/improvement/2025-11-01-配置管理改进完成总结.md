## 🎯 使用示例

### 在 Application 中使用

```cpp
#include "esdk_sophon/vision/VisionConfigLoader.h"
#include "esdk_sophon/vision/PPYoloeDetector.h"
#include "esdk_sophon/core/Config.h"

int main() {
    // 1. 加载全局配置文件
    auto& config = core::Config::getInstance();
    config.load("config/config.json");

    // 2. 使用VisionConfigLoader加载检测器配置
    vision::VisionConfigLoader loader;
    auto detectorConfig = loader.loadDetectorConfig("ppyoloe");

    // 3. 初始化检测器
    auto detector = std::make_unique<vision::PPYoloeDetector>();
    if (!detector->initialize(detectorConfig)) {
        std::cerr << "检测器初始化失败" << std::endl;
        return 1;
    }

    // 4. 使用检测器
    cv::Mat image = cv::imread("test.jpg");
    auto results = detector->detect(image);

    return 0;
}
```

## 📚 知识点总结

### 1. 配置管理最佳实践

**避免硬编码的理由**:

- ❌ 硬编码: 修改需要重新编译
- ✅ 配置文件: 修改无需重新编译
- ✅ 支持多环境配置(开发/测试/生产)
- ✅ 便于团队协作和部署

### 2. 配置分层管理

| 配置层级       | 变化时机 | 灵活性 | 适用场景           |
| -------------- | -------- | ------ | ------------------ |
| **编译时配置** | 编译时   | 低     | 常量、类型参数     |
| **启动时配置** | 启动时   | 中     | 路径、阈值(本项目) |
| **运行时配置** | 运行时   | 高     | 动态参数           |

### 3. 单例模式应用

```cpp
// Config和Logger都是单例
VisionConfigLoader::VisionConfigLoader()
    : config_(Config::getInstance())
    , logger_(Logger::getInstance()) {
}
```

**为什么用引用而不是指针?**

- 单例保证一直存在,不会为 nullptr
- 引用语义更清晰
- 避免 nullptr 检查

### 4. 字符串拼接技巧

```cpp
std::string prefix = "detector." + detectorType + ".";
config.modelPath = config_.getString(prefix + "model_path");
```

灵活支持多种类型:

- `"ppyoloe"` → `"detector.ppyoloe.model_path"`
- `"yolov10"` → `"detector.yolov10.model_path"`

### 5. 默认值策略

```cpp
// 提供默认值并记录警告
std::string path = config_.getString("detector.model_path", "");
if (path.empty()) {
    logger_.warning("未配置模型路径");
    return getDefaultCocoLabels();  // 使用默认值
}
```

## 🎓 面试要点

### Q: 为什么要避免硬编码?

A:

1. 修改配置需要重新编译,不灵活
2. 不同环境难以切换(开发/测试/生产)
3. 不利于团队协作(每个人路径不同)
4. 无法热更新配置

解决方案: 使用配置文件集中管理

### Q: 配置如何分层管理?

A: 三层配置:

1. **编译时**: 宏定义、模板参数(不可变)
2. **启动时**: 配置文件(可变但需重启) ← 本项目采用
3. **运行时**: 配置中心(热更新)

### Q: Config 为什么用单例?

A:

1. 配置应该全局唯一
2. 避免重复加载配置文件
3. 方便全局访问
4. 节省内存

实现: Meyers' Singleton (C++11 保证线程安全)
