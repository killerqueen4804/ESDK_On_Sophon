### **问题 1: FFmpeg 目标名称错误**

**错误信息**:

```
CMake Error at tests/CMakeLists.txt:694 (add_executable):
  Target "test_h264_decoder" links to target "ThirdParty::FFMPEG" but the
  target was not found.
```

**根因**:

- `third_party/CMakeLists.txt` 中定义的是 `ThirdParty::FFmpeg` (首字母大写)
- `tests/CMakeLists.txt` 中使用的是 `ThirdParty::FFMPEG` (全大写)

**修复**:

```cmake
# ❌ 错误
target_link_libraries(test_h264_decoder
    PRIVATE ThirdParty::FFMPEG  # 全大写 - 不存在!
)

# ✅ 正确
target_link_libraries(test_h264_decoder
    PRIVATE ThirdParty::FFmpeg  # 首字母大写 - 正确!
)
```

### **问题 2: Qt AUTOMOC/AUTOUIC/AUTORCC 警告**

**错误信息**:

```
CMake Warning (dev) in src/CMakeLists.txt:
  AUTOGEN: No valid Qt version found for target ESDK_Sophon.
  AUTOMOC, AUTOUIC and AUTORCC disabled.
```

**根因**:

- CMake 默认启用了 Qt 的自动代码生成 (MOC/UIC/RCC)
- 但项目中**没有使用** Qt Widgets 的信号槽机制
- 我们只使用 Qt5Network 和 Qt5Mqtt (纯 C++ API)

**修复**:

```cmake
# ❌ 旧配置 (启用 AUTOMOC)
set(CMAKE_AUTOUIC ON)
set(CMAKE_AUTOMOC ON)
set(CMAKE_AUTORCC ON)

# ✅ 新配置 (禁用 AUTOMOC)
set(CMAKE_AUTOUIC OFF)  # 禁用 .ui 文件处理
set(CMAKE_AUTOMOC OFF)  # 禁用 Qt MOC
set(CMAKE_AUTORCC OFF)  # 禁用 .qrc 资源文件
```

**为什么可以禁用？**

- **MOC** (Meta-Object Compiler): 处理 `Q_OBJECT` 宏,生成信号槽代码
- **UIC** (User Interface Compiler): 处理 Qt Designer 的 `.ui` 文件
- **RCC** (Resource Compiler): 处理 Qt 资源文件 `.qrc`

我们的项目:

- ✅ 使用 Qt5Network::QTcpSocket (纯 C++ API,不需要 MOC)
- ✅ 使用 Qt5Mqtt::QMqttClient (纯 C++ API,不需要 MOC)
- ❌ 不使用 Qt Widgets (没有 UI 界面)
- ❌ 不使用信号槽 (不需要 `Q_OBJECT`)

## 🎓 技术知识点

### **知识点 1: CMake IMPORTED 目标 vs 变量**

**面试问题**: 为什么使用 `ThirdParty::FFmpeg` 而不是 `${FFMPEG_LIBRARIES}`？

**标准答案**:

| 方式                                     | 优点                   | 缺点                             |
| ---------------------------------------- | ---------------------- | -------------------------------- |
| **变量** (`${FFMPEG_LIBRARIES}`)         | 简单                   | 需要手动管理头文件路径、编译选项 |
| **IMPORTED 目标** (`ThirdParty::FFmpeg`) | 自动传递依赖、类型安全 | 需要先创建目标                   |

**CMake 现代实践** (推荐):

```cmake
# 1. 创建 IMPORTED 目标
add_library(ThirdParty::FFmpeg INTERFACE IMPORTED GLOBAL)

# 2. 设置属性
set_target_properties(ThirdParty::FFmpeg PROPERTIES
    INTERFACE_INCLUDE_DIRECTORIES "/path/to/ffmpeg/include"
    INTERFACE_LINK_LIBRARIES "avcodec;avformat;swscale"
)

# 3. 使用目标 (自动获得头文件路径和库)
target_link_libraries(my_target PRIVATE ThirdParty::FFmpeg)
```

**为什么这样设计？**

- **封装**: 隐藏实现细节,只暴露接口
- **传递性**: 自动传递给依赖者
- **类型安全**: CMake 会检查目标是否存在

### **知识点 2: Qt MOC (Meta-Object Compiler)**

**面试问题**: 什么是 Qt MOC？什么时候需要它？

**标准答案**:

**MOC 的作用**:

1. 处理 `Q_OBJECT` 宏
2. 生成信号槽元对象代码
3. 实现 Qt 的反射机制

**示例**:

```cpp
// MyClass.h
class MyClass : public QObject {
    Q_OBJECT  // ← 需要 MOC 处理!

signals:
    void dataReady();

public slots:
    void processData();
};

// MOC 生成 moc_MyClass.cpp:
// - qt_static_metacall()
// - metaObject()
// - 信号槽连接代码
```

**什么时候不需要 MOC？**

- 只使用 Qt 的容器类 (`QString`, `QList`)
- 只使用 Qt 的网络类 (`QTcpSocket`,但不使用信号槽)
- 不使用 `Q_OBJECT` 宏

**本项目的情况**:

```cpp
// ✅ 不需要 MOC
QTcpSocket* socket = new QTcpSocket();
socket->connectToHost("127.0.0.1", 1883);

// ❌ 需要 MOC
class MySocket : public QTcpSocket {
    Q_OBJECT  // ← 使用信号槽,需要 MOC
};
```

### **知识点 3: FFmpeg 头文件组织**

**面试问题**: FFmpeg 的各个库有什么作用？

**标准答案**:

| 库                | 头文件                       | 作用                    |
| ----------------- | ---------------------------- | ----------------------- |
| **libavcodec**    | `libavcodec/avcodec.h`       | 编解码器 (H.264/AAC)    |
| **libavformat**   | `libavformat/avformat.h`     | 封装格式 (MP4/FLV/RTSP) |
| **libavutil**     | `libavutil/imgutils.h`       | 工具函数 (图像处理)     |
| **libswscale**    | `libswscale/swscale.h`       | 颜色空间转换 (YUV↔RGB)  |
| **libswresample** | `libswresample/swresample.h` | 音频重采样              |

**本项目用到的**:

```cpp
#include <libavcodec/avcodec.h>    // avcodec_decode_video2()
#include <libavformat/avformat.h>  // avformat_open_input()
#include <libswscale/swscale.h>    // sws_scale()
#include <libavutil/imgutils.h>    // av_image_get_buffer_size()
```

**为什么分库？**

1. **模块化**: 解码和封装分离,可独立使用
2. **减少依赖**: 只用解码器不需要链接 libavformat
3. **减小体积**: 只链接需要的库
