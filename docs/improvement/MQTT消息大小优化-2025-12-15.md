# MQTT 消息大小优化 - 解决断连问题

**日期**: 2025-12-15  
**问题**: MQTT 消息过大 (4.76 MB) 导致连接断开  
**解决方案**: 图片压缩 + 轮廓简化

---

## 🔍 问题分析

### 现象

```
[DEBUG] 发布消息到主题 [...], QoS=0, 长度=4767015  // 4.76 MB!
[WARN ] 💔 onConnectionLostCallback 被paho调用
[WARN ] MQTT连接丢失: Unknown
[ERROR] 发布消息失败, 主题: ..., 错误码: -1
```

### 根本原因

MQTT 消息大小超过 Broker 限制 (通常 256 KB - 1 MB)

**消息组成**:

1. `resultImage` (Base64 编码的可视化图片) → **~3-4 MB**
2. `objects[].mask` (分割轮廓点 + GPS 坐标) → **~0.5-1 MB**
3. 其他元数据 → **~10 KB**

**问题点**:

- ❌ 原图尺寸太大 (如 4000x3000)
- ❌ JPEG 质量过高 (85%)
- ❌ 轮廓点数过多 (每个对象可能有 100-500 个点)
- ❌ 每个点都包含 GPS 坐标 (lon, lat)

---

## ✅ 优化方案

### 1. **图片尺寸限制**

**位置**: `buildEvent()` 和 `buildSegmentationEvent()`

**修改**:

```cpp
// 🔧 优化: 如果图片太大,先缩放
const int MAX_WIDTH = 1280;   // 最大宽度
const int MAX_HEIGHT = 960;   // 最大高度

if (visFrame.cols > MAX_WIDTH || visFrame.rows > MAX_HEIGHT) {
    double scale = std::min(
        static_cast<double>(MAX_WIDTH) / visFrame.cols,
        static_cast<double>(MAX_HEIGHT) / visFrame.rows
    );

    int newWidth = static_cast<int>(visFrame.cols * scale);
    int newHeight = static_cast<int>(visFrame.rows * scale);

    cv::Mat resized;
    cv::resize(visFrame, resized, cv::Size(newWidth, newHeight), 0, 0, cv::INTER_LINEAR);
    visFrame = resized;
}
```

**效果**:

- 4000x3000 → 1280x960 (缩小 ~9 倍)
- 文件大小减少 ~80%

---

### 2. **降低 JPEG 质量**

**修改**:

```cpp
// JPEG 编码 (使用较低的质量)
int quality = 60;  // 🔧 降低质量: 85 → 60
if (encodeImageToJPEG(visFrame, quality, jpegBuffer)) {
    event.resultImage = encodeBase64(jpegBuffer);
    impl_->logger.info("📦 resultImage 编码完成: JPEG=" + std::to_string(jpegBuffer.size()) +
                       " bytes, Base64=" + std::to_string(event.resultImage.size()) +
                       " chars, quality=" + std::to_string(quality));
}
```

**效果**:

- 质量 85% → 60%
- 文件大小减少 ~40%
- 视觉效果仍然清晰

---

### 3. **轮廓点数量限制** (最关键!)

**修改 1: 增大简化系数**

```cpp
// 使用轮廓点 (激进简化)
std::vector<cv::Point> approx;
double epsilon = 5.0;  // 🔧 增大简化系数: 2.0 → 5.0
cv::approxPolyDP(result.contours, approx, epsilon, true);
```

**修改 2: 强制降采样**

```cpp
// 🔧 进一步降采样: 如果点数仍然太多,按固定间隔采样
const int MAX_MASK_POINTS = 50;  // 最多保留 50 个点
int step = (approx.size() > MAX_MASK_POINTS) ?
          (approx.size() / MAX_MASK_POINTS + 1) : 1;

for (size_t j = 0; j < approx.size(); j += step) {
    const auto& pt = approx[j];
    DetectionEvent::MaskPoint maskPt;
    maskPt.x = pt.x;
    maskPt.y = pt.y;
    maskPt.location.lon = obj.bbox.location.lon;
    maskPt.location.lat = obj.bbox.location.lat;
    obj.mask.push_back(maskPt);
}
```

**效果**:

- 原始: 200-500 个点 → 优化后: 最多 50 个点
- JSON 大小减少 ~90%

## 🎯 为什么这样优化?

### 1. **为什么缩放图片?**

- ✅ **MQTT 限制**: 大多数 Broker 限制 256 KB - 1 MB
- ✅ **网络传输**: 减少带宽消耗
- ✅ **云端显示**: 1280x960 已足够清晰
- ✅ **本地保存**: 可视化图片仍然保存原始分辨率

### 2. **为什么降低 JPEG 质量?**

- ✅ **人眼不敏感**: 60% vs 85% 肉眼几乎看不出差别
- ✅ **检测框清晰**: 绘制的框和文字仍然清晰
- ✅ **压缩率高**: 质量降低 25% → 文件大小减少 40%

### 3. **为什么简化轮廓?**

- ✅ **形状保留**: epsilon=5.0 仍然能保留轮廓主要形状
- ✅ **GPS 冗余**: 每个点的 GPS 都差不多,不需要精确到每个像素
- ✅ **性能优化**: 减少 JSON 解析时间

## 💡 进一步优化方案 (可选)

### 方案 1: 不发送 resultImage

如果云端不需要可视化图片,可以直接删除:

```cpp
// event.resultImage = "";  // 不发送图片
```

### 方案 2: 使用 WebP 格式

WebP 压缩率比 JPEG 高 25-35%:

```cpp
cv::imencode(".webp", visFrame, jpegBuffer, {cv::IMWRITE_WEBP_QUALITY, 60});
```

### 方案 3: 分离上传

将 `resultImage` 通过单独的 HTTP/OSS 上传,MQTT 只发送 URL:

```json
{
  "result": {
    "imageUrl": "https://oss.example.com/seg_12345.jpg",
    "objects": [...]
  }
}
```

## 📚 相关知识点

### 1. **MQTT QoS 级别**

- QoS 0: 最多发送一次 (不保证送达)
- QoS 1: 至少发送一次 (可能重复)
- QoS 2: 恰好发送一次 (最慢)

**当前使用**: QoS 0 (最快,适合实时数据)

### 2. **JPEG 质量 vs 文件大小**

```
Quality 100: 原始质量, 文件大
Quality  85: 高质量, 肉眼几乎无差别
Quality  60: 中等质量, 性价比最高 ✅
Quality  30: 低质量, 明显压缩痕迹
```

### 3. **轮廓简化算法 (Douglas-Peucker)**

`cv::approxPolyDP(contour, approx, epsilon, closed)`

- epsilon: 简化精度 (越大越简化)
- epsilon = 2.0: 保留细节
- epsilon = 5.0: 中等简化 ✅
- epsilon = 10.0: 激进简化

**Q: 如何优化 MQTT 消息大小?**

A:

1. **图片压缩**: 缩小分辨率 + 降低 JPEG 质量
2. **数据精简**: 轮廓简化 + 降采样
3. **协议优化**: 使用二进制格式 (Protocol Buffers)
4. **分离传输**: 大文件通过 OSS,MQTT 只传元数据
