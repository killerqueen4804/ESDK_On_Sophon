## 📋 改进背景

### 问题现状

用户在查看日志时遇到两个问题:

1. **SAM2 未启用原因不明**

   ```
   [WARN] ❌ [TaskService] SAM2 未启用,无法执行分割任务: taskId=4295
   ```

   - 不知道是配置文件设置的 `enabled=false` 还是初始化失败
   - 缺少初始化过程的日志

2. **检测流程信息不足**
   ```
   [INFO] ℹ️ 未检测到关注的目标: DJI_20251212094543_0002_V_-suffix.jpeg（正常，继续处理下一张）
   ```
   - 不知道检测器是否运行成功
   - 不知道检测到了多少个原始目标
   - 不知道过滤后剩余多少目标

### 改进目标

✅ **SAM2 初始化透明化**: 完整记录初始化流程,包括配置读取、文件检查、模型加载  
✅ **检测流程可视化**: 详细记录检测器调用、原始结果、过滤过程  
✅ **错误诊断友好化**: 提供明确的错误原因和排查建议

## 🔧 改进内容

### 1. SAM2 初始化日志增强

**修改位置**: `TaskService::Impl` 构造函数

**新增日志**:

```cpp
logger.info("🔧 [SAM2 初始化] enabled=" + std::string(enabled ? "true" : "false"));

if (enabled) {
    logger.info("🔧 [SAM2 初始化] 正在加载模型...");
    logger.info("  📦 Encoder: " + encoderPath);
    logger.info("  📦 Decoder: " + decoderPath);
    logger.info("  🔌 Device ID: " + std::to_string(deviceId));

    // 文件存在性检查
    std::ifstream encoderFile(encoderPath);
    if (!encoderFile.good()) {
        logger.error("❌ [SAM2 初始化] Encoder 模型文件不存在: " + encoderPath);
        useSam2 = false;
        return;
    }

    logger.info("🚀 [SAM2 初始化] 正在调用 init()...");
    if (!sam2Segmentor->init(encoderPath, decoderPath)) {
        logger.error("❌ [SAM2 初始化] init() 返回 false (模型加载失败)");
        useSam2 = false;
    } else {
        logger.info("✅ [SAM2 初始化] 初始化成功! useSam2=true");
    }
} else {
    logger.info("ℹ️ [SAM2 初始化] 配置文件中已禁用 (segmentation.sam2.enabled=false)");
}
```

**改进点**:

1. **配置读取**: 明确显示 `enabled` 标志的值
2. **文件检查**: 初始化前检查模型文件是否存在
3. **流程追踪**: 记录每个关键步骤的执行状态
4. **结果确认**: 最终输出 `useSam2` 的实际值

## 📊 日志级别使用规范

### INFO 级别 (用户关注的关键信息)

- ✅ SAM2 初始化状态
- ✅ 检测器调用和结果数量
- ✅ 过滤后的目标数量
- ✅ 事件构建和发布状态
- ✅ 文件处理成功/失败

### DEBUG 级别 (开发调试信息)

- 🔍 检测框详细信息 (类别、置信度、坐标)
- 🔍 中间处理步骤的细节

### WARNING 级别 (需要注意但不影响运行)

- ⚠️ SAM2 未启用但收到分割任务
- ⚠️ 检测器调用失败
- ⚠️ 未检测到关注的目标

### ERROR 级别 (严重错误)

- ❌ 模型文件不存在
- ❌ 模型初始化失败
- ❌ MQTT 发布失败
- ❌ 异常捕获

## 📝 新增文件检查功能

为了避免因模型文件不存在导致的初始化失败,新增了文件存在性检查:

```cpp
#include <fstream>  // 新增头文件

// 检查 Encoder 模型文件
std::ifstream encoderFile(encoderPath);
if (!encoderFile.good()) {
    logger.error("❌ [SAM2 初始化] Encoder 模型文件不存在: " + encoderPath);
    useSam2 = false;
    return;
}

// 检查 Decoder 模型文件
std::ifstream decoderFile(decoderPath);
if (!decoderFile.good()) {
    logger.error("❌ [SAM2 初始化] Decoder 模型文件不存在: " + decoderPath);
    useSam2 = false;
    return;
}
```

**优点**:

- 提前发现文件不存在的问题
- 避免 BMRuntime 内部报错难以定位
- 给出清晰的错误提示

## 📚 知识点讲解

### 📌 日志级别设计原则

#### 知识点

日志级别(Log Level)是软件工程中的最佳实践,用于控制日志输出的详细程度。

常见级别:

- **ERROR**: 严重错误,需要立即处理
- **WARNING**: 潜在问题,不影响运行但需要注意
- **INFO**: 关键信息,业务流程节点
- **DEBUG**: 调试信息,开发阶段使用
- **TRACE**: 详细追踪,性能敏感场景不建议使用

#### 项目中的例子

```cpp
// ❌ 错误: 所有日志都用 INFO
logger.info("检测器初始化成功");  // 可以
logger.info("检测框详情: x=100, y=200");  // 太详细,应该用 DEBUG

// ✅ 正确: 合理使用日志级别
logger.info("✅ [检测任务] 检测器返回 5 个原始检测框");  // 关键信息
logger.debug("📋 [检测任务] 原始检测框详情:");  // 详细调试信息
logger.debug("  [0] person (ID=0, conf=0.85, ...)");
```

#### 面试要点

**Q: 为什么要使用日志级别?**

A:

1. **性能优化**: DEBUG 日志在生产环境可关闭,减少 I/O 开销
2. **信息过滤**: 根据场景选择合适的日志级别,避免日志淹没
3. **快速定位**: ERROR/WARNING 日志帮助快速发现问题
4. **可维护性**: 清晰的日志分级便于后期维护
