## 🎯 TaskManager 核心设计

### 1. 单例模式 - Meyers' Singleton

**为什么用单例？**

- 任务管理器在全局只需要一个实例
- 多个模块（MQTT、Vision、Device）都需要访问同一个任务列表
- 避免多个实例导致状态不一致

**实现方式**:

```cpp
// TaskManager.h
class TaskManager {
public:
    static TaskManager& getInstance();

    // 禁止拷贝和赋值
    TaskManager(const TaskManager&) = delete;
    TaskManager& operator=(const TaskManager&) = delete;

private:
    TaskManager();  // 私有构造函数
};

// TaskManager.cpp
TaskManager& TaskManager::getInstance() {
    static TaskManager instance;  // Meyers' Singleton
    return instance;
}
```

**为什么不用双检锁（DCL）？**

❌ **传统 DCL（不推荐）**:

```cpp
static TaskManager* instance = nullptr;
static std::mutex mtx;

TaskManager& getInstance() {
    if (instance == nullptr) {          // 第一次检查
        std::lock_guard<std::mutex> lock(mtx);
        if (instance == nullptr) {      // 第二次检查
            instance = new TaskManager();
        }
    }
    return *instance;
}
```

✅ **C++11 后推荐（Meyers' Singleton）**:

```cpp
TaskManager& getInstance() {
    static TaskManager instance;  // C++11保证线程安全初始化
    return instance;
}
```

**优势**:

1. **线程安全**: C++11 标准保证局部静态变量只初始化一次
2. **简洁**: 无需手动加锁，编译器自动处理
3. **无内存泄漏**: 自动析构，无需 delete
4. **懒加载**: 第一次调用时才初始化

### 2. TPU 资源管理

**TPU vs GPU 的关键区别**:

| 特性     | NVIDIA GPU        | 算能 TPU         |
| -------- | ----------------- | ---------------- |
| 设计目标 | 通用并行计算      | 专用深度学习推理 |
| 内存架构 | 独立显存(GDDR6)   | 可能共享系统内存 |
| 并发模型 | CUDA 流、多上下文 | SDK 调度         |
| 资源管理 | 手动管理显存      | SDK 封装         |

**资源状态结构**:

```cpp
struct TpuResourceStatus {
    int availableMemoryMB;      ///< 可用显存(MB)
    int totalMemoryMB;          ///< 总显存(MB)
    float utilizationPercent;   ///< TPU利用率(0-100%)
    int runningTaskCount;       ///< 当前运行的任务数量

    bool hasEnoughResource(int estimatedMemoryMB) const {
        return availableMemoryMB >= estimatedMemoryMB;
    }
};
```

**资源检查流程**:

```cpp
bool TaskManager::startTask(const types::TaskConfig& config) {
    // 1. 预估显存占用
    int requiredMemory = estimateTpuMemory(config);

    // 2. 获取TPU状态
    TpuResourceStatus tpuStatus = getTpuResourceStatus();

    // 3. 检查资源是否充足
    if (!tpuStatus.hasEnoughResource(requiredMemory)) {
        // 资源不足，加入等待队列
        waitingQueue_.push(config);
        return true;
    }

    // 4. 资源充足，创建任务
    TaskState taskState(config.taskId, config);
    taskState.estimatedTpuMemoryMB = requiredMemory;
    runningTasks_.emplace(config.taskId, std::move(taskState));

    return true;
}
```

**显存预估策略**:

```cpp
int TaskManager::estimateTpuMemory(const types::TaskConfig& config) const {
    int baseMemory = 512;  // 基础开销

    for (const auto& algo : config.algorithmTypes) {
        if (algo.name == "目标检测") {
            baseMemory += 800;  // YOLOv5/v10
        } else if (algo.name == "语义分割") {
            baseMemory += 1200; // 分割模型更大
        } else if (algo.name == "实例分割") {
            baseMemory += 1500;
        }
    }

    return baseMemory;
}
```

**面试要点**:

- Q: 为什么要预估显存占用？
- A: TPU 显存有限（如 4GB），多个任务并发时可能 OOM。预估可以提前拒绝或排队，避免运行时崩溃。

### 3. 多任务并发控制

**冲突检测规则**:

```cpp
TaskConflictAction TaskManager::checkTaskConflict(
    const types::TaskConfig& newConfig) const {

    // 规则1: 超过最大并发数 -> 排队
    if (runningTasks_.size() >= maxConcurrentTasks_) {
        return TaskConflictAction::QUEUE;
    }

    // 规则2: 视频流任务互斥
    if (newConfig.liveviewTaskType) {
        for (const auto& pair : runningTasks_) {
            if (pair.second.config.liveviewTaskType) {
                return TaskConflictAction::QUEUE;  // 或 STOP_OLD
            }
        }
    }

    // 规则3: 图片任务可以并发
    return TaskConflictAction::CONCURRENT;
}
```

**冲突解决策略**:

```cpp
enum class TaskConflictAction {
    REJECT,         ///< 拒绝新任务
    QUEUE,          ///< 加入等待队列
    STOP_OLD,       ///< 停止旧任务
    PAUSE_OLD,      ///< 暂停旧任务
    CONCURRENT      ///< 并发执行
};
```

**实际场景**:

| 场景            | 策略       | 原因                           |
| --------------- | ---------- | ------------------------------ |
| 视频流 + 视频流 | QUEUE      | 硬件限制，只能同时处理一路视频 |
| 图片 + 图片     | CONCURRENT | TPU 可以并行处理多个图片       |
| 图片 + 视频流   | CONCURRENT | 不冲突，可以同时进行           |
| 超过最大并发数  | QUEUE      | 避免 TPU 过载                  |

**等待队列处理**:

```cpp
void TaskManager::processWaitingQueue() {
```

## 🔧 线程安全设计

### 互斥锁使用

**原则**: 所有访问共享状态的公共方法都加锁

```cpp
class TaskManager {
private:
    mutable std::mutex mutex_;  // mutable允许在const方法中加锁
    std::map<std::string, TaskState> runningTasks_;
    std::queue<types::TaskConfig> waitingQueue_;

public:
    bool startTask(const types::TaskConfig& config) {
        std::lock_guard<std::mutex> lock(mutex_);  // RAII锁
        // ... 访问 runningTasks_ ...
    }

    TaskStatus getTaskStatus(const std::string& taskId) const {
        std::lock_guard<std::mutex> lock(mutex_);  // const方法也要加锁
        // ... 只读访问也要保护 ...
    }
};
```

**为什么 const 方法也要加锁？**

```cpp
// 线程1
TaskStatus status = manager.getTaskStatus("task1");  // 读

// 线程2（同时执行）
manager.stopTask("task1");  // 写 - 删除 runningTasks_["task1"]

// 如果不加锁，线程1可能读到已删除的数据，导致崩溃！
```

**mutable 关键字**:

```cpp
class TaskManager {
private:
    mutable std::mutex mutex_;  // 必须用 mutable

public:
    TaskStatus getTaskStatus(const std::string& taskId) const {
        // 如果没有 mutable，这里编译错误：
        // 不能在 const 方法中修改成员变量 mutex_
        std::lock_guard<std::mutex> lock(mutex_);
        // ...
    }
};
```

## 📊 性能优化点

### 1. 避免长时间持有锁

❌ **错误示例**（推理时持有锁）:

```cpp
void processMediaFile(const std::string& taskId, const std::string& file) {
    std::lock_guard<std::mutex> lock(mutex_);  // ❌ 不要这样！

    // 推理可能需要几十毫秒到几秒
    auto result = runInference(file);  // 阻塞其他线程！

    runningTasks_[taskId].processedMediaFiles++;
}
```

✅ **正确示例**（只在更新状态时加锁）:

```cpp
void processMediaFile(const std::string& taskId, const std::string& file) {
    // 1. 推理时不持有锁
    auto result = runInference(file);

    // 2. 只在更新状态时加锁
    {
        std::lock_guard<std::mutex> lock(mutex_);
        auto it = runningTasks_.find(taskId);
        if (it != runningTasks_.end()) {
            it->second.processedMediaFiles++;
        }
    }  // 锁自动释放
}
```

## 🎓 面试要点总结

### 单例模式

**Q: 单例模式有哪些实现方式？**

A:

1. **饿汉式**: 程序启动时就创建（线程安全但浪费内存）
2. **懒汉式**: 第一次使用时创建（需要加锁）
3. **双检锁**: 减少加锁开销（C++11 前有内存序问题）
4. **Meyers' Singleton**: C++11 局部静态变量（推荐）

**Q: 为什么 Meyers' Singleton 是线程安全的？**

A: C++11 标准规定，局部静态变量的初始化是线程安全的。编译器会生成类似以下的代码：

```cpp
// 伪代码
static bool initialized = false;
static std::mutex init_mutex;

if (!initialized) {
    lock_guard<mutex> lock(init_mutex);
    if (!initialized) {
        // 初始化
        initialized = true;
    }
}
```

### 线程安全

**Q: 如何设计线程安全的类？**

A:

1. **互斥锁保护**: 所有访问共享状态的方法加锁
2. **const 方法也要加锁**: 读操作也需要保护（用 mutable mutex）
3. **最小化锁范围**: 只在必要时持有锁
4. **避免死锁**: 统一加锁顺序，避免嵌套锁

**Q: std::lock_guard 和 std::unique_lock 的区别？**

A:

- `lock_guard`: RAII 锁，构造时加锁，析构时解锁，不能手动控制
- `unique_lock`: 更灵活，支持手动 lock/unlock、延迟加锁、条件变量

本项目中使用 `lock_guard` 因为足够简单。

### RAII 原则

**Q: 什么是 RAII？项目中如何应用？**

A: RAII (Resource Acquisition Is Initialization) - 资源获取即初始化

**本项目中的应用**:

1. **智能指针管理任务辅助对象**:

```cpp
struct TaskState {
    std::unique_ptr<CompletionDetector> detector;
    std::unique_ptr<MediaFileFilter> fileFilter;
    // TaskState 析构时，自动释放这些对象
};
```

2. **std::lock_guard 管理锁**:

```cpp
{
    std::lock_guard<std::mutex> lock(mutex_);
    // ... 临界区 ...
}  // 离开作用域，锁自动释放（即使发生异常也会释放）
```

3. **任务删除时自动清理**:

```cpp
bool TaskManager::stopTask(const std::string& taskId) {
    runningTasks_.erase(it);
    // TaskState 析构 -> unique_ptr 析构 -> 辅助对象自动释放
}
```
