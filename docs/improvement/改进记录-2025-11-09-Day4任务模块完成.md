### 问题 1: TaskConfig 类型冲突 (types:: vs task::)

**现象**:

```cpp
error: reference to 'TaskConfig' is ambiguous
```

**原因**:

- `types::TaskConfig` (旧的 MQTT 数据结构)
- `task::TaskConfig` (新的任务配置结构)
- 两个命名空间都有同名类型

**解决方案**:

1. 在 `task::TaskConfig` 中添加静态工厂方法:
   ```cpp
   static TaskConfig fromJson(const nlohmann::json& json);
   ```
2. 创建 `src/task/TaskTypes.cpp` 实现 JSON 解析
3. 简化 `MqttHandler.cpp` 中的类型转换 (-60 行代码)

**影响文件**:

- `include/esdk_sophon/task/TaskTypes.h` (新增方法声明)
- `src/task/TaskTypes.cpp` (新增文件)
- `src/Mqtt/MqttHandler.cpp` (简化代码)
- `src/task/CMakeLists.txt` (添加 TaskTypes.cpp)

**知识点**:

- **静态工厂方法**: 相比构造函数更灵活,可以返回子类,可以有清晰的语义名称
- **单一职责原则**: JSON 解析逻辑放在数据结构本身,而非外部转换函数

### 问题 2: EventType 解析错误

**现象**:

```cpp
error: no matching function for call to EventType::EventType(int&)
```

**原因**:
错误地将 EventType 当作枚举类型使用 `static_cast<EventType>(id)`,但实际上 EventType 是一个结构体:

```cpp
struct EventType {
    int id;
    int mainType;
    std::string eventDescribe;
    std::vector<int> classIds;
};
```

**解决方案**:
正确构造 EventType 对象:

```cpp
EventType eventType;
eventType.id = typeObj.value("id", 0);
eventType.mainType = typeObj.value("main_type", 0);
eventType.eventDescribe = typeObj.value("name", "");
```

**知识点**:

- **结构体 vs 枚举**: 结构体需要构造,枚举是编译时常量
- **JSON 字段映射**: `value()` 方法提供默认值,比 `at()` 更安全

### 问题 4: OpenCV/GStreamer 链接警告 (200+条)

**现象**:

```
warning: libz.so.1, needed by libopencv_core.so, not found
warning: libjpeg.so.8, needed by libopencv_core.so, not found
... (200+ warnings)
```

**原因**:
交叉编译环境中的共享库依赖在运行时才解析,编译时找不到

**解决方案**:
添加链接器标志:

```cmake
set(CMAKE_EXE_LINKER_FLAGS "${CMAKE_EXE_LINKER_FLAGS} -Wl,--unresolved-symbols=ignore-in-shared-libs")
set(CMAKE_SHARED_LINKER_FLAGS "${CMAKE_SHARED_LINKER_FLAGS} -Wl,--unresolved-symbols=ignore-in-shared-libs")
```

**原理**:

- 编译时: 忽略共享库中的未定义符号
- 运行时: 动态链接器 (ld.so) 在 SE7 设备上加载真实的 .so 文件

**风险**:

- 如果 SE7 设备缺少某些库,程序运行时会失败
- 需要用 `ldd` 命令检查依赖

**实际运行时问题**:

```bash
# SE7设备上运行时报错
error while loading shared libraries: libdc1394.so.22: cannot open shared object file

# 解决: 安装缺失的库
sudo apt-get install libdc1394-22
```

### 问题 6: TaskService 构造函数参数检查

**现象**:

```
❌ 测试失败: TaskService: mqtt 参数不能为 nullptr
```

**原因**:
测试代码中传入 `nullptr`:

```cpp
std::shared_ptr<mqtt::MqttClient> mqttClient = nullptr;
auto service = std::make_shared<TaskService>(mqttClient);  // 抛出异常
```

但 TaskService 构造函数检查参数:

```cpp
TaskService::TaskService(std::shared_ptr<mqtt::MqttClient> mqtt) {
    if (!mqtt) {
        throw std::invalid_argument("TaskService: mqtt 参数不能为 nullptr");
    }
}
```

**解决方案**:
使用 MqttClient 单例:

```cpp
auto mqttClientPtr = std::shared_ptr<esdk_sophon::mqtt::MqttClient>(
    &esdk_sophon::mqtt::MqttClient::getInstance(),
    [](esdk_sophon::mqtt::MqttClient*) {} // 空删除器
);
auto service = std::make_shared<TaskService>(mqttClientPtr);
```

**知识点**:

- **单例模式**: MqttClient 全局唯一,通过 `getInstance()` 获取
- **shared_ptr 自定义删除器**: 单例对象不应该被 `delete`,需要空删除器
- **Meyers 单例**: 局部静态变量,C++11 保证线程安全

### 问题 7: TaskManager 未初始化导致段错误

**现象**:

```
[ERROR] TaskManager 未初始化,无法创建任务
Segmentation fault (core dumped)
```

**原因**:
TaskManager 的 `createTask()` 方法在未初始化时返回 `nullptr`,测试代码没有检查:

```cpp
auto task = manager.createTask(config);  // 返回 nullptr
task->getConfig();  // ❌ 空指针解引用
```

**解决方案**:
在调用 `createTask()` 前先初始化 TaskManager:

```cpp
TaskManager& manager = TaskManager::getInstance();
bool initialized = manager.initialize(mqttClientPtr);
assert(initialized && "TaskManager 初始化失败!");
```

**知识点**:

- **RAII 原则**: 资源获取即初始化,TaskManager 需要先初始化才能使用
- **前置条件检查**: 在使用对象前验证其状态
- **错误处理**: 使用 assert 在测试中快速失败

## 🎓 技术知识点总结

### C++ 核心概念

1. **静态工厂方法 vs 构造函数**

   ```cpp
   // 构造函数: 名字固定,返回类型固定
   TaskConfig(const std::string& id);

   // 静态工厂方法: 语义清晰,可以返回子类
   static TaskConfig fromJson(const nlohmann::json& json);
   static TaskConfig fromDatabase(int taskId);
   ```

2. **单例模式的正确使用**

   ```cpp
   // Meyers 单例 (C++11线程安全)
   static MqttClient& getInstance() {
       static MqttClient instance;  // 局部静态变量
       return instance;
   }

   // 获取 shared_ptr (需要自定义删除器)
   auto ptr = std::shared_ptr<MqttClient>(
       &MqttClient::getInstance(),
       [](MqttClient*) {}  // 空删除器,不delete单例
   );
   ```

3. **智能指针的自定义删除器**

   ```cpp
   // 默认删除器: delete ptr
   std::shared_ptr<int> p1(new int(42));

   // 自定义删除器: 可以是任何可调用对象
   std::shared_ptr<FILE> p2(
       fopen("file.txt", "r"),
       [](FILE* f) { fclose(f); }  // 关闭文件而非delete
   );
   ```

4. **RAII (Resource Acquisition Is Initialization)**
   ```cpp
   class TaskManager {
   public:
       bool initialize(/* 资源 */);  // 获取资源
       void shutdown();              // 释放资源
       ~TaskManager() { shutdown(); } // 析构时自动释放
   };
   ```

### CMake 交叉编译

1. **链接器选项控制**

   ```cmake
   # 忽略共享库中的未定义符号
   set(CMAKE_EXE_LINKER_FLAGS
       "${CMAKE_EXE_LINKER_FLAGS} -Wl,--unresolved-symbols=ignore-in-shared-libs")
   ```

2. **编译时 vs 运行时依赖**
   - 编译时: 只需要头文件 (.h) 和库接口
   - 运行时: 需要真实的共享库 (.so)

### JSON 解析最佳实践

```cpp
// ❌ 不安全: 字段缺失会抛异常
int id = json.at("id").get<int>();

// ✅ 安全: 提供默认值
int id = json.value("id", 0);

// ✅ 检查字段存在性
if (json.contains("type") && json["type"].is_array()) {
    // 处理数组
}
```
