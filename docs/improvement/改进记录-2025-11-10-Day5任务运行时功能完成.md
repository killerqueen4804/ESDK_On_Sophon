### 2. 状态机设计

```
任务生命周期状态转换图:

    IDLE ──start()──> RUNNING ──pause()──> PAUSED
     ↑                   │                    │
     │                   │                    │
     └───────stop()──────┴───resume()─────────┘
                         │
                         └──> COMPLETED/FAILED/CANCELLED
```

**状态枚举** (TaskTypes.h):

```cpp
enum class TaskState {
    IDLE = 0,       // 空闲 (未初始化)
    PENDING,        // 待启动 (已创建,等待资源)
    RUNNING,        // 运行中
    PAUSED,         // 暂停 (可恢复)
    COMPLETED,      // 完成 (正常结束)
    FAILED,         // 失败 (异常终止)
    CANCELLED       // 取消 (用户中止)
};
```

### 3. 线程安全机制

#### 同步原语使用

- **`std::atomic<TaskState>`**: 任务状态 (无锁读写)
- **`std::mutex`**: 保护统计数据 (避免数据竞争)
- **`std::condition_variable`**: 暂停/恢复机制 (高效等待)
- **`std::unique_lock`**: RAII 锁管理 (异常安全)

#### 线程生命周期管理

```cpp
// 启动线程
workerThread_ = std::thread(&LiveStreamTask::processLoop, this);

// 停止线程
shouldStop_.store(true);           // 设置停止标志
pauseCondition_.notify_all();      // 唤醒可能在等待的线程
if (workerThread_.joinable()) {
    workerThread_.join();          // 等待线程退出
}
```

### 4. 回调机制

#### 状态回调

```cpp
using StateCallback = std::function<void(const std::string& taskId, TaskState state)>;

void setStateCallback(StateCallback callback) override {
```

## 🔧 技术难点与解决方案

### 难点 1: 枚举类型输出到流

**问题**: `TaskState` 和 `TaskType` 枚举无法直接用 `operator<<` 输出。

**解决方案**: 在测试文件中重载输出操作符

```cpp
inline std::ostream& operator<<(std::ostream& os, TaskState state) {
    switch (state) {
        case TaskState::IDLE: return os << "IDLE";
        case TaskState::RUNNING: return os << "RUNNING";
        // ... 其他状态
        default: return os << "UNKNOWN(" << static_cast<int>(state) << ")";
    }
}
```

**面试要点**:

- 枚举类型不是内置类型,需要显式转换才能输出
- `operator<<` 重载要放在枚举所在命名空间或测试文件中
- 使用 `inline` 避免重定义错误

### 难点 2: MqttClient 单例与 shared_ptr

**问题**: `MqttClient` 是单例(私有构造函数),但 `TaskService` 需要 `shared_ptr<MqttClient>`。

**错误尝试**:

```cpp
// ❌ 错误: MqttClient 构造函数是私有的
auto mqttClient = std::make_shared<mqtt::MqttClient>();

// ❌ 错误: TaskService 要求 mqtt 不能为 nullptr
return std::make_shared<TaskService>(nullptr);
```

**正确解决方案**: 使用 `shared_ptr` 的别名构造函数

```cpp
std::shared_ptr<TaskService> createTestTaskService() {
    // 1. 获取单例引用
    mqtt::MqttClient& mqttInstance = mqtt::MqttClient::getInstance();

    // 2. 创建不拥有所有权的 shared_ptr
    std::shared_ptr<mqtt::MqttClient> mqttPtr(
        std::shared_ptr<mqtt::MqttClient>(),  // 空的控制块
        &mqttInstance                          // 指向单例的指针
    );

    // 3. 传递给 TaskService
    return std::make_shared<TaskService>(mqttPtr);
}
```

**面试要点**:

- **单例模式**: 保证全局只有一个实例,私有构造函数防止外部创建
- **shared_ptr 别名构造函数**: `shared_ptr<T>(shared_ptr<U>, T*)`
  - 第一个参数提供引用计数控制块(可以为空)
  - 第二个参数是实际指向的对象
  - 析构时不会删除对象(因为控制块为空)
- **依赖注入**: TaskService 通过构造函数注入依赖,而非内部创建
- **测试技巧**: 在单例场景下如何创建测试用的智能指针

### 难点 3: 暂停/恢复的竞态条件

**问题**: 如何保证 `pause()` 和 `resume()` 的正确性,避免死锁和虚假唤醒?

**解决方案**: 标准的条件变量模式

```cpp
// processLoop() 中:
while (!shouldStop_.load()) {
    {
        std::unique_lock<std::mutex> lock(pauseMutex_);
        pauseCondition_.wait(lock, [this] {
            return !isPaused_.load() || shouldStop_.load();
        });
    }

    if (shouldStop_.load()) break;

    // 处理帧...
}

// pause() 中:
bool LiveStreamTask::pause() {
    if (state_.load() != TaskState::RUNNING) {
        return false;
    }

    isPaused_.store(true);
    state_.store(TaskState::PAUSED);

    if (stateCallback_) {
        stateCallback_(config_.taskId, TaskState::PAUSED);
    }

    return true;
}

// resume() 中:
bool LiveStreamTask::resume() {
    if (state_.load() != TaskState::PAUSED) {
        return false;
    }

    isPaused_.store(false);
    state_.store(TaskState::RUNNING);
    pauseCondition_.notify_all();  // 唤醒工作线程

    if (stateCallback_) {
        stateCallback_(config_.taskId, TaskState::RUNNING);
    }

    return true;
}
```

**面试要点**:

- **条件变量**: `std::condition_variable` 用于线程间通信
- **虚假唤醒**: `wait()` 可能在没有 `notify()` 的情况下返回,需要用 lambda 谓词检查
- **互斥锁**: `unique_lock` 在 `wait()` 时自动释放锁,返回时重新获取
- **notify_all() vs notify_one()**: `notify_all()` 更安全,唤醒所有等待线程

### 难点 4: RAII 资源清理

**问题**: 如何保证任务对象销毁时线程已经正确停止?

**解决方案**: 析构函数中调用 `stop()`

```cpp
LiveStreamTask::~LiveStreamTask() {
    // 确保任务已停止(幂等性)
    stop();

    logger_.info("LiveStreamTask 已销毁: taskId=" + config_.taskId);
}
```

**面试要点**:

- **RAII (Resource Acquisition Is Initialization)**:
  - 构造函数获取资源
  - 析构函数释放资源
  - 利用 C++ 对象生命周期自动管理资源
- **异常安全**: 即使发生异常,析构函数也会被调用
- **幂等性**: `stop()` 可以多次调用而不出错

## 💡 设计模式应用

### 1. 状态模式 (State Pattern)

**应用场景**: 任务状态转换

```cpp
// 状态转换由状态机控制
bool LiveStreamTask::start() {
    TaskState expected = TaskState::IDLE;
    if (!state_.compare_exchange_strong(expected, TaskState::RUNNING)) {
        logger_.error("无法启动任务: 当前状态不是 IDLE");
        return false;
    }
    // ...
}
```

### 2. 观察者模式 (Observer Pattern)

**应用场景**: MediaFileTask 文件通知

```cpp
// MediaFileTask 作为观察者,注册到 MediaFilesObserver
void MediaFileTask::start() {
    registerMediaFilesObserver();  // 注册为观察者
}

void MediaFileTask::onMediaFileUpdate(const std::string& filePath) {
    // 收到通知,加入队列
    fileQueue_.push(filePath);
    queueCondition_.notify_one();
}
```

### 3. 生产者-消费者模式 (Producer-Consumer)

**应用场景**: MediaFileTask 文件队列

```cpp
// 生产者: onMediaFileUpdate() 入队
void MediaFileTask::onMediaFileUpdate(const std::string& filePath) {
    std::lock_guard<std::mutex> lock(queueMutex_);
    fileQueue_.push(filePath);
    queueCondition_.notify_one();  // 通知消费者
}

// 消费者: processLoop() 出队
void MediaFileTask::processLoop() {
    while (!shouldStop_.load()) {
        std::unique_lock<std::mutex> lock(queueMutex_);
        queueCondition_.wait(lock, [this] {
            return !fileQueue_.empty() || shouldStop_.load();
        });

        if (!fileQueue_.empty()) {
            std::string filePath = fileQueue_.front();
            fileQueue_.pop();
            lock.unlock();

            readMediaFile(filePath);  // 处理文件
        }
    }
}
```

### 4. RAII 模式 (Resource Acquisition Is Initialization)

**应用场景**: 线程生命周期管理

```cpp
class LiveStreamTask {
    ~LiveStreamTask() {
        stop();  // 析构时自动停止线程,释放资源
    }

private:
    std::thread workerThread_;  // 使用 RAII 管理线程
};
```

### 5. Pimpl 模式 (Pointer to Implementation)

**应用场景**: TaskService 隐藏实现细节

```cpp
// TaskService.h
class TaskService {
public:
    TaskService(std::shared_ptr<mqtt::MqttClient> mqtt);
    ~TaskService();

private:
    struct Impl;
    std::unique_ptr<Impl> impl_;  // 隐藏实现细节
};

// TaskService.cpp
struct TaskService::Impl {
    std::shared_ptr<mqtt::MqttClient> mqtt;
    std::unordered_map<std::string, ...> lastReportTime;
    // ... 内部实现
};
```
