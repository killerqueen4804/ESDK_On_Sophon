## ✅ 正确理解

### MediaFileTask 的实际工作流程

参考文件: `ESDK_On_Sophon/src/task/MediaFileTask.cpp` (行 346-380)

```cpp
// ✅ 正确实现
bool MediaFileTask::registerMediaFilesObserver() {
    Logger::info("注册 MediaFilesObserver: taskId=" + config_.taskId);

    // 实际实现 (参考 Edge-SDK/examples/media_manager/sample_read_media_file.cc)
    auto rc = MediaManager::Instance()->RegisterMediaFilesObserver(
        std::bind(&MediaFileTask::onMediaFileUpdate, this, std::placeholders::_1));

    if (rc != kOk) {
        Logger::error("注册 MediaFilesObserver 失败");
        return false;
    }

    return true;
}

void MediaFileTask::onMediaFileUpdate(const MediaFileInfo& file) {
    Logger::info("收到媒体文件更新通知: " + file.file_name);

    // 将文件信息放入队列
    {
        std::lock_guard<std::mutex> lock(queueMutex_);
        fileQueue_.push(file);
        queueCv_.notify_one();
    }
}
```

### 完整工作流程

```
1. start() 启动任务
   ↓
2. registerMediaFilesObserver()
   注册观察者，监听 DJI 机场的新文件通知
   ↓
3. onMediaFileUpdate(MediaFileInfo)
   回调函数：收到 DJI SDK 推送的文件信息
   → 将 MediaFileInfo 放入队列
   → 通知工作线程
   ↓
4. processLoop() 工作线程
   → 从队列取出 MediaFileInfo
   → readMediaFile() 读取文件内容到内存
   → cv::imdecode() 解码为 cv::Mat
   → service_->processFrame() 调用推理
   ↓
5. stop() 停止任务
   → unregisterMediaFilesObserver()
   → 清空队列
```

### MediaFileTask 的核心特点

| 特性         | LiveStreamTask                  | MediaFileTask                        |
| ------------ | ------------------------------- | ------------------------------------ |
| **数据源**   | RTSP/RTMP 网络视频流            | DJI 机场媒体文件（图片/视频）        |
| **连接方式** | `cv::VideoCapture::open(url)`   | `RegisterMediaFilesObserver()`       |
| **数据获取** | `capture->read(frame)` 实时读帧 | `MediaFilesReader->Read()` 读取文件  |
| **处理模式** | 持续处理，断流重连              | 事件驱动，队列处理                   |
| **线程模型** | 单线程循环读帧                  | 回调线程 + 工作线程（生产者-消费者） |
| **解码方式** | VideoCapture 自动解码           | `cv::imdecode()` 从内存解码          |
| **结束条件** | 手动 stop()                     | 手动 stop()                          |

**新增知识点**:

4. **内存管理**: 文件内容读取到 `std::vector<uint8_t>`，自动管理内存
5. **解码**: `cv::imdecode()` 直接从内存解码，无需临时文件

### 2. MediaFileTask 的设计为什么是这样？

**DJI 的设计考虑**:

1. **网络传输**: 机场和边缘计算设备不在同一机器
2. **异步处理**: 文件上传是异步的，需要事件通知
3. **资源管理**: 文件可能很大，需要流式读取
4. **灵活性**: 支持多种文件格式（图片、视频）

**为什么不是本地文件**:

- ❌ 如果是本地文件，直接用 `cv::VideoCapture` 即可
- ❌ 不需要复杂的观察者模式和队列
- ✅ DJI 需要从远程机场读取，所以设计了 `MediaManager` + `MediaFilesReader`

### 3. 生产者-消费者模式的应用

**为什么需要队列？**

```
回调线程 (生产者)          工作线程 (消费者)
     ↓                         ↓
onMediaFileUpdate()       processLoop()
     ↓                         ↓
fileQueue_.push()        fileQueue_.pop()
     ↓                         ↓
queueCv_.notify_one()    queueCv_.wait()
```

**好处**:

1. **解耦**: 回调线程和处理线程独立运行
2. **缓冲**: 队列缓存待处理文件，处理速度可以不同
3. **线程安全**: 通过 mutex 和 condition_variable 保证安全

### 4. DJI SDK 的 MediaManager 架构

```
DJI Dock (机场)
    ↓ (上传媒体文件)
MediaManager (DJI SDK)
    ↓ (通知)
MediaFilesObserver (用户注册)
    ↓ (回调)
onMediaFileUpdate(MediaFileInfo)
    ↓
MediaFilesReader (读取文件)
    ↓
应用程序处理
```

**关键组件**:

- `MediaManager`: 管理媒体文件，提供观察者注册
- `MediaFilesObserver`: 观察者回调接口
- `MediaFileInfo`: 文件元信息（名称、路径、大小）
- `MediaFilesReader`: 文件读取接口（Open/Read/Close）

### 面试回答模板

**Q: MediaFileTask 是如何工作的？**

A: MediaFileTask 负责处理从 DJI 机场上传的媒体文件。它的工作流程是：

1. **注册观察者**: 调用 `MediaManager::RegisterMediaFilesObserver()` 注册回调函数
2. **接收通知**: DJI SDK 检测到新文件时，调用 `onMediaFileUpdate(MediaFileInfo)` 推送文件信息
3. **队列缓存**: 回调函数将 `MediaFileInfo` 放入队列，通过条件变量唤醒工作线程
4. **读取文件**: 工作线程使用 `MediaFilesReader` 读取文件内容到内存 (`std::vector<uint8_t>`)
5. **解码处理**: 使用 `cv::imdecode()` 解码图片，然后调用推理
6. **清理资源**: stop() 时注销观察者，清空队列

这个设计采用了**观察者模式**（接收通知）和**生产者-消费者模式**（队列处理），实现了异步、解耦的文件处理。

与 LiveStreamTask 的区别在于：

- LiveStreamTask 处理实时视频流，使用 cv::VideoCapture 持续读帧
- MediaFileTask 处理离散文件，使用事件驱动 + 队列处理
