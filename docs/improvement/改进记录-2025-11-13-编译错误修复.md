### 问题 1: TaskConfig 缺少 detectionEnabled 字段

#### 错误信息

```
/workspace/src/task/LiveStreamTask.cpp:425:37: error: 'struct esdk_sophon::task::TaskConfig' has no member named 'detectionEnabled'
  425 |     bool detectionEnabled = config_.detectionEnabled;
      |                                     ^~~~~~~~~~~~~~~~
```

#### 问题分析

**根本原因**：

- `LiveStreamTask.cpp` 中使用了 `config_.detectionEnabled` 字段
- 但 `TaskTypes.h` 中的 `TaskConfig` 结构体没有定义该字段
- 这是代码演进过程中遗漏的字段定义

**使用场景**：

```cpp
// LiveStreamTask.cpp 第 425 行
bool detectionEnabled = config_.detectionEnabled;  // 从配置读取

if (detectionEnabled) {
    // 只有启用检测时才将 H264 数据加入队列
    std::lock_guard<std::mutex> lock(h264Mutex_);
    h264Queue_.emplace(buf, buf + len);
    h264Condition_.notify_one();
}
```

**字段作用**：

- 控制是否启用视觉检测功能
- 当 `detectionEnabled = false` 时，H264 数据直接推流，不经过检测处理
- 当 `detectionEnabled = true` 时，H264 数据会被加入队列，等待检测处理

#### 解决方案

**修改文件**: `include/esdk_sophon/task/TaskTypes.h`

**修改 1: 添加字段声明**

```cpp
// ===== 执行控制 =====
bool detectionEnabled;           ///< 是否启用视觉检测 (默认true)
int reportIntervalSec;           ///< 事件上报间隔 (秒, 默认10)
bool enableVisualization;        ///< 是否生成可视化图像
int maxDetectionsPerFrame;       ///< 每帧最大检测数 (0=无限制)
```

**修改 2: 更新构造函数默认值**

```cpp
TaskConfig()
    : taskId("")
    , type(TaskType::UNKNOWN)
    , algorithmId(0)
    , confidenceThreshold(0.5f)
    , nmsThreshold(0.45f)
    , source(DataSource::LIVESTREAM)
    , mediaPath("")
    , detectionEnabled(true)          // ← 新增，默认启用检测
    , reportIntervalSec(10)
    , enableVisualization(true)
    , maxDetectionsPerFrame(100)
    , enableRTMP(false)
    , rtmpUrl("")
    , rtmpWidth(800)
    , rtmpHeight(600)
    , rtmpFps(25)
    , deviceSn("")
{}
```

**设计决策**：

- **默认值为 `true`**：保持向后兼容，现有任务默认启用检测
- **可配置**：允许用户在创建任务时根据需求关闭检测（例如只做推流）

### 问题 2: RtmpStreamer.h 多行注释警告

#### 警告信息

```
/workspace/include/esdk_sophon/rtmp/RtmpStreamer.h:478:1: warning: multi-line comment [-Wcomment]
  478 | // gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux ! \
      | ^
```

#### 问题分析

**根本原因**：

- C++ 单行注释 `//` 中使用了反斜杠 `\` 作为换行符
- 编译器将 `\` 识别为行连接符（line continuation），认为注释跨越多行
- 这会导致后续代码被误认为注释的一部分

**错误代码**：

```cpp
// gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux ! \
//   rtmpsink location=rtmp://localhost/live/test
```

**编译器理解**：

```cpp
// gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux !
  rtmpsink location=rtmp://localhost/live/test  // ← 这行被认为是注释的一部分！
```

#### 解决方案

**修改文件**: `include/esdk_sophon/rtmp/RtmpStreamer.h`

**修改前**：

````cpp
// **命令行测试**：
// ```bash
// # 测试 RTMP 推流
// gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux ! \
//   rtmpsink location=rtmp://localhost/live/test
// ```
````

**修改后**：

````cpp
// **命令行测试**：
// ```bash
// # 测试 RTMP 推流
// gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux !
//   rtmpsink location=rtmp://localhost/live/test
// ```
````

**关键改动**：

- 移除了 `flvmux !` 后面的反斜杠 `\`
- 保持缩进，表示这是同一条命令的延续

**替代方案**：
如果需要强调这是一条完整的命令，可以写成单行：

```cpp
// gst-launch-1.0 videotestsrc ! x264enc ! h264parse ! flvmux ! rtmpsink location=rtmp://localhost/live/test
```

## 📚 知识点：C++ 注释中的陷阱

### 1. 单行注释中的反斜杠

**错误示例**：

```cpp
// 这是一个很长的注释，我想换行 \
   但这会导致下一行也被注释！
int x = 10;  // ← 这行代码不会执行！
```

**正确做法**：

```cpp
// 方法 1: 不用反斜杠，直接写多行注释
// 这是一个很长的注释，我想换行
// 这是第二行注释
int x = 10;  // ✅ 正常执行

// 方法 2: 使用多行注释
/*
 * 这是一个很长的注释，
 * 可以随意换行
 */
int x = 10;  // ✅ 正常执行
```

### 2. 为什么反斜杠会连接行？

**C/C++ 预处理规则**：

- 编译器在处理代码前，会先进行预处理（preprocessing）
- 预处理器会将反斜杠 `\` 后面的换行符删除，连接两行

**示例**：

```cpp
// 源代码
#define LONG_STRING "This is a very long string \
that spans multiple lines"

// 预处理后
#define LONG_STRING "This is a very long string that spans multiple lines"
```

**注释中的行连接**：

```cpp
// 源代码
// Comment line 1 \
// Comment line 2

// 预处理后
// Comment line 1 // Comment line 2
```

### 3. 面试高频考点

**Q1: 为什么下面的代码会报错？**

```cpp
// This is a comment \
int x = 10;  // 这行代码不会执行
```

**标准答案**：

> 单行注释 `//` 中的反斜杠 `\` 是行连接符，会将下一行也注释掉。  
> 预处理器会删除 `\` 和换行符，导致 `int x = 10;` 也成为注释的一部分。  
> 正确做法是移除反斜杠，或使用多行注释 `/* ... */`。

**Q2: `//` 和 `/* */` 的区别？**

| 特性       | `//` 单行注释   | `/* */` 多行注释 |
| ---------- | --------------- | ---------------- |
| 作用范围   | 当前行          | 可跨多行         |
| 嵌套       | ✅ 可以嵌套     | ❌ 不能嵌套      |
| 反斜杠影响 | ⚠️ 会连接下一行 | ✅ 不受影响      |
| 常用场景   | 简短说明        | 函数/类文档      |

**Q3: 如何安全地注释掉多行代码？**

**标准答案**：

```cpp
// 方法 1: 使用 #if 0 (推荐)
#if 0
    int x = 10;
    int y = 20;
    // 这里的注释也会被忽略
#endif

// 方法 2: 每行加 //
// int x = 10;
// int y = 20;

// 方法 3: 使用 /* */ (不推荐，可能嵌套冲突)
/*
int x = 10;
int y = 20;
*/
```

## 📝 经验总结

### ✅ 最佳实践

1. **字段添加的完整流程**：

   ```
   1. 在结构体中声明字段（添加注释说明用途）
   2. 在构造函数中初始化默认值
   3. 如果有 isValid() 方法，添加校验逻辑
   4. 如果有 fromJson() 方法，添加解析逻辑
   5. 更新相关文档和测试用例
   ```

2. **注释编写规范**：

   - 单行注释避免使用反斜杠 `\`
   - 命令行示例可以分行，但不要用反斜杠连接
   - 文档注释优先使用 `/** */` 格式（Doxygen 风格）

3. **编译警告的重要性**：
   - `-Wcomment` 警告虽然不影响功能，但会污染编译输出
   - 应及时修复所有警告，保持代码整洁
   - 可以在 CMake 中启用 `-Werror` 将警告视为错误

### ❌ 常见错误

1. **结构体字段遗漏**：

   ```cpp
   // ❌ 错误：只添加了字段，忘记初始化
   struct Config {
       bool detectionEnabled;  // 声明了
   };
   Config() {}  // 忘记初始化，值是随机的！

   // ✅ 正确
   Config() : detectionEnabled(true) {}
   ```

2. **注释中的特殊字符**：

   ```cpp
   // ❌ 错误：反斜杠会连接下一行
   // long command \

   // ✅ 正确：去掉反斜杠
   // long command
   ```

3. **默认值选择不当**：

   ```cpp
   // ❌ 错误：默认值为 false，破坏向后兼容
   bool detectionEnabled = false;

   // ✅ 正确：默认值为 true，保持向后兼容
   bool detectionEnabled = true;
   ```
