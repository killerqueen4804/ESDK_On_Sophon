# RTMP 颜色修复记录 (I420 方案)

## [2025-11-19] 修复 RTMP 推流颜色通道交换问题 (方案 B)

### 问题描述

用户反馈 RTMP 推流画面颜色异常（"Blue Face" 现象），即红色和蓝色通道互换。
之前的尝试（直接推送 BGR 数据并设置 Caps 为 BGR）未能解决问题，说明 GStreamer 的 `videoconvert` 插件在处理 BGR 格式时可能存在兼容性问题或行为不符合预期。

### 解决方案

为了彻底规避 RGB/BGR 颜色空间转换的歧义，决定采用 **I420 (YUV420P)** 方案：

1. **OpenCV 转换**: 使用 OpenCV 的 `cv::cvtColor(frame, yuv, cv::COLOR_BGR2YUV_I420)` 将 BGR 图像转换为标准的 I420 格式。OpenCV 的颜色转换经过严格验证，结果可靠。
2. **GStreamer Caps**: 将 `appsrc` 的 Caps 设置为 `video/x-raw, format=I420`。
3. **Pipeline**: `appsrc` 输出 I420 数据，`videoconvert` 将直接透传（因为 `x264enc` 原生支持 I420），避免了 GStreamer 内部的颜色转换逻辑。

### 代码变动

**文件**: `src/rtmp/RtmpStreamer.cpp`

#### 1. 修改 Caps 设置

```cpp
GstCaps* caps = gst_caps_new_simple(
    "video/x-raw",
    "format", G_TYPE_STRING, "I420",    // ✅ 改为 I420
    // ...
);
```

#### 2. 修改颜色转换逻辑

```cpp
// 使用 OpenCV 进行转换
cv::Mat yuv;
cv::cvtColor(processed, yuv, cv::COLOR_BGR2YUV_I420);

// 计算缓冲区大小 (Width * Height * 1.5)
size_t bufferSize = width_ * height_ * 3 / 2;
```

### 预期效果

1. **颜色正确**: OpenCV 负责 BGR 到 YUV 的转换，确保 U/V 通道顺序正确。
2. **兼容性好**: I420 是最通用的视频格式，几乎所有编码器都支持。
3. **性能**: 虽然增加了一次 OpenCV 转换，但避免了 GStreamer 内部可能的多次转换，整体性能影响可控。
