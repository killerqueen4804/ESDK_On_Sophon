# RTMP 颜色修复记录

## [2025-11-19] 修复 RTMP 推流颜色通道交换问题

### 问题描述

用户反馈 RTMP 推流画面颜色异常（"Blue Face" 现象），即红色和蓝色通道互换。
例如：人脸显示为蓝色，蓝色物体显示为红色。

### 原因分析

经过代码审查和逻辑推演，发现问题出在颜色空间转换逻辑上：

1. **H264Decoder 输出**: `H264Decoder` 内部使用 `sws_scale` (YUV->RGB) 然后 `cv::cvtColor` (RGB->BGR)。虽然代码意图是输出 BGR，但如果 `sws_scale` 输出的 RGB 实际上被 OpenCV 解释为 BGR（或者反之），或者 `cvtColor` 的行为与预期不符，可能导致输出实际上是 RGB。
2. **RtmpStreamer 处理**: `RtmpStreamer` 接收到帧后，执行了 `cv::cvtColor(BGR2RGB)`，然后将 Caps 设置为 "RGB"。
3. **GStreamer 行为**: GStreamer 接收到数据并被告知是 "RGB"。如果数据实际上是 BGR（因为 `H264Decoder` 输出 RGB，`RtmpStreamer` 转换后变成 BGR），那么 GStreamer 会将 B 解析为 R，导致颜色互换。

**推测**: `H264Decoder` 实际上输出了 RGB 数据（尽管代码试图转换为 BGR），或者 `RtmpStreamer` 的转换导致了二次交换。

### 解决方案

为了简化逻辑并提高性能，决定统一使用 OpenCV 的默认格式 **BGR**：

1. **修改 RtmpStreamer**:
   - 移除 `cv::cvtColor(BGR2RGB)` 转换，直接使用输入的 BGR 数据。
   - 将 GStreamer 的 Caps 从 `"format", "RGB"` 改为 `"format", "BGR"`。
   - 这样 GStreamer 管道 (`appsrc ! videoconvert ! ...`) 会自动处理 BGR 到 I420 的转换。

### 代码变动

**文件**: `src/rtmp/RtmpStreamer.cpp`

#### 1. 修改 Caps 设置

```cpp
// 旧代码
GstCaps* caps = gst_caps_new_simple(
    "video/x-raw",
    "format", G_TYPE_STRING, "RGB",  // ❌ 错误：导致颜色混淆
    // ...
);

// 新代码
GstCaps* caps = gst_caps_new_simple(
    "video/x-raw",
    "format", G_TYPE_STRING, "BGR",  // ✅ 正确：直接使用 OpenCV 默认格式
    // ...
);
```

#### 2. 移除颜色转换

```cpp
// 旧代码
} else if (processed.channels() == 3) {
    cv::cvtColor(processed, rgb, cv::COLOR_BGR2RGB); // ❌ 移除不必要的转换
}

// 新代码
} else if (processed.channels() == 3) {
    rgb = processed; // ✅ 直接传递 BGR 数据
}
```

### 预期效果

1. **颜色正确**: 画面颜色应恢复正常。
2. **性能提升**: 减少了一次全图的 `cv::cvtColor` 调用，降低 CPU 占用。
3. **逻辑简化**: 整个管道（解码 -> 处理 -> 推流）统一使用 BGR 格式，减少了混淆。

### 验证计划

1. 编译并运行程序。
2. 观察 RTMP 推流画面，确认人脸颜色是否自然。
3. 如果颜色仍然错误（例如变成绿色或紫色），则说明数据格式可能不是 BGR/RGB，而是 YUV 或其他，需要进一步排查 `H264Decoder`。
