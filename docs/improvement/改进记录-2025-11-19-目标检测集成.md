# 改进记录 - 2025-11-19 - 目标检测集成与问题修复

## 1. 日志乱码修复 (Log Encoding Fix)

### 问题描述

在 Windows 环境下（尤其是 MobaXterm/Notepad），日志文件显示乱码。原因是 `std::locale` 设置与 Windows 默认编码（GBK）冲突，且日志文件缺少 UTF-8 BOM 头。

### 解决方案

1. **移除 `std::locale`**: 不再依赖系统 locale，强制使用 UTF-8。
2. **添加 BOM 头**: 在创建新日志文件时，写入 UTF-8 BOM (`0xEF, 0xBB, 0xBF`)，帮助编辑器识别编码。
3. **强制 UTF-8 输出**: 确保所有字符串在写入文件前都是 UTF-8 编码。

### 修改文件

- `src/core/Logger.cpp`

## 2. RTMP 颜色修复 (RTMP Color Fix)

### 问题描述

RTMP 推流画面颜色异常（"阿凡达"蓝皮肤），原因是 OpenCV 默认使用 BGR 格式，而 GStreamer 管道期望 I420 (YUV420P) 格式。

### 解决方案

1. **格式转换**: 在推流前，使用 `cv::cvtColor(frame, yuvFrame, cv::COLOR_BGR2YUV_I420)` 将 BGR 转换为 I420。
2. **数据拷贝**: 将转换后的 I420 数据拷贝到 GStreamer buffer 中。

### 修改文件

- `src/task/RtmpStreamer.cpp` (假设在之前的步骤中已修改，本次记录作为汇总)

## 3. 目标检测集成 (Object Detector Integration)

### 目标

将真实的 AI 推理引擎 (`PPYoloeDetector`) 集成到任务处理流程中，替代之前的模拟检测（Dummy Box）。

### 实施步骤

#### 3.1 TaskService 改造

- **引入检测器**: 在 `TaskService::Impl` 中集成 `vision::IDetector`。
- **初始化**: 在构造函数中通过 `DetectorFactory` 创建 `PPYoloeDetector` 实例。
- **接口优化**: 重载 `processFrame` 方法，增加 `std::vector<BoundingBox>& outBoxes` 输出参数，以便外部获取检测结果。

#### 3.2 LiveStreamTask 优化

- **消除重复检测**: 之前 `LiveStreamTask` 为了可视化会再次调用 `detectObjects`，导致每帧推理两次（性能减半）。
- **流程整合**: 现在调用 `service_->processFrame(..., boxes)` 一次性完成检测、过滤、上报，并获取结果用于 RTMP 可视化。

### 修改文件

- `include/esdk_sophon/task/TaskService.h`
- `src/task/TaskService.cpp`
- `src/task/LiveStreamTask.cpp`
