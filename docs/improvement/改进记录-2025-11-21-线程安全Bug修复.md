## 🔍 根因分析

### 问题代码

```cpp
class MockMqttPublisher {
public:
    bool publish(const std::string& topic, const std::string& payload) {
        publishCount++;  // ❌ 非原子操作
        topics.push_back(topic);  // ❌ std::vector 不是线程安全

        // ❌ std::cout 不是线程安全
        std::cout << "  [Mock MQTT] 发布事件: topic=" << topic
                  << ", payload_size=" << payload.size() << "\n";

        return shouldSucceed;
    }
};
```

### 并发场景

```
时间线：
Thread 1: std::cout << "topic="
Thread 2: std::cout << "topic="  ← 插入
Thread 1: std::cout << "drone/event/thread1"
Thread 2: std::cout << "drone/event/thread2"
结果：    "topic=drone/event/thread2drone/event/thread1"  ← 混乱
```

### 为什么会段错误？

1. **`publishCount++` 数据竞争**

   ```cpp
   // 等价于（非原子）：
   int temp = publishCount;  // Thread 1 读取
   // <-- Thread 2 同时读取同一个值
   temp = temp + 1;
   publishCount = temp;      // Thread 1 写回
   // <-- Thread 2 写回，覆盖 Thread 1 的结果
   ```

2. **`topics.push_back()` 内存损坏**

   ```cpp
   // std::vector 可能触发扩容（reallocation）
   Thread 1: topics.push_back("A");  // 触发扩容
            ↓
            分配新内存、拷贝数据、释放旧内存
            ↓
   Thread 2: topics.push_back("B");  // 访问已释放的旧内存 → Segment Fault!
   ```

3. **`std::cout` 输出混乱**
   - `operator<<` 不是原子操作
   - 多个线程同时写，缓冲区混乱
   - 可能访问无效指针

## 🔧 修复方案

### 方案对比

| 方案              | 优点                 | 缺点                 | 适用场景  |
| ----------------- | -------------------- | -------------------- | --------- |
| **A. 添加互斥锁** | 彻底解决，支持多线程 | 性能开销（~20ns/次） | 生产环境  |
| **B. 关闭输出**   | 零开销               | 调试困难             | 性能测试  |
| **C. 单线程测试** | 简单                 | 无法测试并发         | ❌ 不适用 |

**最终选择**：**方案 A（互斥锁） + 方案 B（可选关闭输出）**

### 修复后的代码

```cpp
class MockMqttPublisher {
public:
    bool shouldSucceed = true;
    int publishCount = 0;
    std::vector<std::string> topics;
    bool enableOutput = true;  // ⭐ 新增：控制输出

    bool publish(const std::string& topic, const std::string& payload) {
        // ⭐ 线程安全：互斥锁保护所有共享数据
        std::lock_guard<std::mutex> lock(mutex_);

        publishCount++;
        topics.push_back(topic);

        // ⭐ 可选输出（多线程测试时关闭）
        if (enableOutput) {
            std::cout << "  [Mock MQTT] 发布事件: topic=" << topic
                      << ", payload_size=" << payload.size()
                      << ", result=" << (shouldSucceed ? "成功" : "失败") << "\n";
        }

        return shouldSucceed;
    }

    void reset() {
        std::lock_guard<std::mutex> lock(mutex_);  // ⭐ reset 也需要加锁
        publishCount = 0;
        topics.clear();
        shouldSucceed = true;
        enableOutput = true;
    }

private:
    std::mutex mutex_;  // ⭐ 互斥锁
};
```

## 📚 知识点总结

### 1. 线程安全的三层含义

#### Level 1: 数据竞争（Data Race）

多个线程同时访问同一内存，至少一个是写操作。

**例子**：

```cpp
int count = 0;
Thread 1: count++;  // 读-改-写
Thread 2: count++;  // 读-改-写
// 可能结果：count = 1（应该是 2）
```

**解决方案**：

- `std::mutex`：互斥锁
- `std::atomic<int>`：原子变量

---

#### Level 2: 对象状态不一致

**例子**：

```cpp
class BankAccount {
    int balance = 100;

    void transfer(int amount) {
        balance -= amount;  // ← 如果这里被打断
        // ... 通知对方账户 ...
        // balance 已扣款，但对方未收到 → 不一致
    }
};
```

**解决方案**：

- 事务（Transaction）：要么全成功，要么全失败
- 锁住整个操作

---

#### Level 3: 死锁（Deadlock）

**例子**：

```cpp
Thread 1: lock(A); lock(B);  // 等待 B
Thread 2: lock(B); lock(A);  // 等待 A
// 互相等待 → 死锁
```

**解决方案**：

- 固定加锁顺序：总是先锁 A，再锁 B
- 超时机制：`std::unique_lock::try_lock_for()`
- 死锁检测：定期检查

---

### 2. `std::lock_guard` vs `std::unique_lock`

| 特性     | `std::lock_guard` | `std::unique_lock`                |
| -------- | ----------------- | --------------------------------- |
| 加锁方式 | 构造时自动加锁    | 构造时可选加锁                    |
| 解锁方式 | 析构时自动解锁    | 析构时或手动解锁                  |
| 可移动   | ❌ 不可移动       | ✅ 可移动                         |
| 手动解锁 | ❌ 不支持         | ✅ `unlock()`                     |
| 延迟加锁 | ❌ 不支持         | ✅ `std::defer_lock`              |
| 条件变量 | ❌ 不支持         | ✅ 配合 `std::condition_variable` |
| 性能     | ⚡ 更快（零开销） | 稍慢（灵活性）                    |

**使用建议**：

- **简单场景**：用 `std::lock_guard`（本次修复）
- **需要手动解锁**：用 `std::unique_lock`
- **条件变量**：必须用 `std::unique_lock`

**代码示例**：

```cpp
// ✅ 简单场景：lock_guard
void simple() {
    std::lock_guard<std::mutex> lock(mutex_);
    // ... 临界区 ...
}  // 自动解锁

// ✅ 复杂场景：unique_lock
void complex() {
    std::unique_lock<std::mutex> lock(mutex_);
    // ...
    lock.unlock();  // 手动解锁
    // ... 做些不需要锁的事 ...
    lock.lock();    // 重新加锁
}
```

### 3. RAII 在线程安全中的应用

**RAII** = Resource Acquisition Is Initialization（资源获取即初始化）

**核心思想**：

- **构造函数**获取资源（加锁）
- **析构函数**释放资源（解锁）
- **保证**：即使异常，也会解锁

**对比手动加锁**：

```cpp
// ❌ 手动加锁（危险）
void bad() {
    mutex.lock();

    if (error) {
        return;  // 忘记解锁 → 死锁！
    }

    throw std::exception();  // 忘记解锁 → 死锁！

    mutex.unlock();
}

// ✅ RAII 自动解锁（安全）
void good() {
    std::lock_guard<std::mutex> lock(mutex_);  // 构造时加锁

    if (error) {
        return;  // 析构时自动解锁 ✅
    }

    throw std::exception();  // 栈展开，析构时自动解锁 ✅
}  // 正常返回，析构时自动解锁 ✅
```

### 4. 为什么 `std::cout` 不是线程安全？

**标准规定**：

- C++ 标准保证：`std::cout` 的**字符级别**是线程安全的
- **不保证**：`operator<<` 的**表达式级别**线程安全

**实验**：

```cpp
// Thread 1
std::cout << "Hello" << " " << "World\n";
//           ^^^^^1    ^2    ^^^^^3

// Thread 2
std::cout << "Foo" << " " << "Bar\n";
//           ^^^4    ^5    ^^^6

// 可能的输出（步骤交错）：
// 1 → 4 → 5 → 2 → 6 → 3
// "HelloFoo BarWorld\n"  ← 混乱
```

**解决方案**：

```cpp
// 方案 A：锁住整个表达式
{
    std::lock_guard<std::mutex> lock(cout_mutex);
    std::cout << "Thread " << id << " says hello\n";
}

// 方案 B：使用日志库（推荐）
Logger::getInstance().info("Thread " + std::to_string(id) + " says hello");
// Logger 内部已加锁
```

## 🎯 面试要点

### Q1: 如何判断一个类是否线程安全？

**A**: 检查以下几点：

1. **成员变量是否被多线程访问？**
   - 是 → 需要保护
2. **有没有互斥锁？**
   - `std::mutex` 成员变量
3. **STL 容器是否线程安全？**
   - **否**（`std::vector`, `std::map` 都不是）
   - 需要手动加锁
4. **是否使用了全局变量？**
   - `std::cout`、静态变量 → 需要保护

---

### Q2: 为什么段错误难以调试？

**A**:

1. **非确定性**：每次运行结果不同
2. **时序相关**：快速运行可能不出错，慢速运行崩溃
3. **堆栈损坏**：错误发生时，调用栈已被破坏
4. **多线程交错**：难以重现

**调试技巧**：

- 使用 ThreadSanitizer（`-fsanitize=thread`）
- 添加日志（注意日志本身的线程安全）
- Core Dump 分析（`gdb core`）
- Valgrind Helgrind 工具

---

### Q3: 什么时候用锁，什么时候用原子变量？

**A**:

| 场景                      | 使用                | 原因             |
| ------------------------- | ------------------- | ---------------- |
| 简单计数器                | `std::atomic<int>`  | 无锁，性能高     |
| 复杂对象（`std::vector`） | `std::mutex`        | 原子操作无法保护 |
| 多个变量一起修改          | `std::mutex`        | 需要事务性       |
| 高并发读、少写            | `std::shared_mutex` | 读写锁           |

**示例**：

```cpp
// ✅ 简单计数：原子变量
std::atomic<int> counter{0};
counter++;  // 原子操作，无需锁

// ✅ 复杂对象：互斥锁
std::vector<int> data;
std::mutex mutex_;
{
    std::lock_guard<std::mutex> lock(mutex_);
    data.push_back(42);
}
```
