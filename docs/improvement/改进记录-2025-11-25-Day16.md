# 改进记录 - Day 16: 架构升级与死锁攻坚

**日期**: 2025-11-25  
**作者**: ESDK Sophon Team  
**主题**: Liveview 单例模式重构、死锁修复、编译权限修正

## 1. 问题背景

在集成 DJI Liveview SDK 时，我们遇到了严重的稳定性问题：

1.  **死锁 (Deadlock)**: 停止任务时，调用 `liveview_->DeInit()` 或析构 `Liveview` 对象会导致程序永久卡死。
2.  **资源泄漏**: 尝试使用"流放线程"（Fire-and-Forget）方案绕过死锁，但导致后台线程和内存不断累积，不适合长期运行。
3.  **编译错误**: 引入静态代理回调后，无法访问 `LiveStreamTask` 的私有成员函数。

## 2. 解决方案：单例模式 (Singleton Pattern)

为了彻底解决死锁和资源泄漏问题，我们将 `Liveview` 的生命周期管理从"随任务创建销毁"改为"全局单例，永久复用"。

### 2.1 架构变更

| 特性         | 旧架构 (Instance per Task)         | 新架构 (Singleton)                       |
| :----------- | :--------------------------------- | :--------------------------------------- |
| **生命周期** | 每次 `start()` 创建，`stop()` 销毁 | 首次 `start()` 创建，程序结束才销毁      |
| **持有方式** | `LiveStreamTask` 成员变量独占      | 全局 `static shared_ptr`，任务仅持有引用 |
| **回调机制** | Lambda 捕获 `this` 指针            | 静态 Proxy 函数 + `g_activeTask` 路由    |
| **停止逻辑** | 调用 `DeInit()` (导致死锁)         | 仅调用 `StopH264Stream()`，保留对象      |

### 2.2 关键代码实现

**全局上下文 (Global Context):**

```cpp
namespace {
    // 全局唯一的 Liveview 实例
    std::shared_ptr<edge_sdk::Liveview> g_liveviewInstance = nullptr;
    std::mutex g_liveviewInitMutex;

    // 活跃任务指针 (路由表)
    std::atomic<LiveStreamTask*> g_activeTask{nullptr};

    // 静态代理回调
    edge_sdk::ErrorCode ProxyH264Callback(const uint8_t* buf, uint32_t len) {
        LiveStreamTask* task = g_activeTask.load();
        if (task) {
            return task->onH264Data(buf, len); // 转发
        }
        return edge_sdk::kOk;
    }
}
```

**初始化逻辑 (Init):**

```cpp
std::lock_guard<std::mutex> lock(g_liveviewInitMutex);
g_activeTask.store(this); // 注册路由

if (!g_liveviewInstance) {
    // 首次创建
    g_liveviewInstance = edge_sdk::CreateLiveview();
    // ... 初始化配置，使用 ProxyH264Callback ...
}
liveview_ = g_liveviewInstance; // 复用
```

**清理逻辑 (Deinit):**

```cpp
g_activeTask.store(nullptr); // 注销路由
liveview_->StopH264Stream(); // 仅停止流
liveview_.reset();           // 释放本地引用，全局对象保持存活
// 不再调用 DeInit()，避免死锁
```

## 3. 编译修复：访问权限

**问题**: `ProxyH264Callback` 是外部静态函数，无法调用 `LiveStreamTask::onH264Data` (Private)。

**修复**: 将回调处理函数移至 `public` 区域。

```cpp
class LiveStreamTask : public ITask {
public:
    // ...
    // 供 Proxy 使用的公共回调
    edge_sdk::ErrorCode onH264Data(const uint8_t* buf, uint32_t len);
    void onLiveviewStatusChanged(const edge_sdk::Liveview::LiveviewStatus& status);
    // ...
};
```

## 4. 验证计划

1.  **功能验证**: 视频流能否正常启动、解码、检测、推流。
2.  **稳定性验证**: 连续多次 `start()` / `stop()`，观察内存是否增长，程序是否卡死。
3.  **并发验证**: 在任务运行时快速切换状态。

## 5. 经验总结

- **SDK 集成原则**: 对于闭源且不稳定的 SDK，"不折腾"是最高准则。如果析构有问题，就不要析构它。
- **架构模式**: 单例模式在嵌入式/SDK 集成场景中非常有用，特别是针对昂贵或脆弱的硬件资源。
- **C++ 技巧**: `std::atomic` 指针是实现无锁回调路由的利器。
