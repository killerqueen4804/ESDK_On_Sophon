## 📋 改进背景

### 问题描述

在之前的实现中，智能变焦拍照功能会在检测到目标后自动触发，不论无人机当前处于什么飞行状态。这导致了一个问题：

> **当无人机执行返航（RTH）或降落时，智能变焦拍照仍会触发，这是不必要且可能影响飞行安全的行为。**

### 用户需求

用户明确提出：

> "无人机返航后就不需要进行智能变焦拍照了"

### 技术分析

根据 DJI Cloud API 文档，飞行器 OSD 数据中包含 `mode_code` 字段，表示当前的飞行模式：

| mode_code | 状态名称     | 说明                 |
| --------- | ------------ | -------------------- |
| 0         | 待机         | Standby              |
| 5         | 航线飞行     | 正常作业状态         |
| **9**     | **自动返航** | **需要暂停变焦拍照** |
| **10**    | **自动降落** | **需要暂停变焦拍照** |
| **11**    | **强制降落** | **需要暂停变焦拍照** |

## 🔧 解决方案

### 1. 添加飞行模式枚举 (FlightDataProvider.h)

```cpp
/**
 * @brief 飞行模式枚举
 *
 * 根据 DJI Cloud API 文档的 mode_code 字段定义。
 */
enum class FlightMode {
    kStandby = 0,           ///< 待机
    kAutoTakeoff = 4,       ///< 自动起飞
    kWaypointFlight = 5,    ///< 航线飞行 (正常作业)
    kAutoRth = 9,           ///< 自动返航 ⚠️
    kAutoLanding = 10,      ///< 自动降落 ⚠️
    kForcedLanding = 11,    ///< 强制降落 ⚠️
    // ... 其他状态
};
```

### 2. 添加飞行状态查询接口 (FlightDataProvider.h)

```cpp
class FlightDataProvider {
public:
    // 更新飞行模式 (由 MqttHandler 调用)
    void updateFlightMode(int modeCode);

    // 获取当前飞行模式
    FlightMode getFlightMode() const;

    // 🔑 核心方法: 检查是否处于返航/降落状态
    bool isReturningOrLanding() const {
        return flightMode_ == FlightMode::kAutoRth ||
               flightMode_ == FlightMode::kAutoLanding ||
               flightMode_ == FlightMode::kForcedLanding;
    }

    // 获取飞行模式的中文名称
    std::string getFlightModeString() const;

private:
    FlightMode flightMode_{FlightMode::kStandby};
};
```

### 3. 在 MqttHandler 中解析 mode_code (MqttHandler.cpp)

```cpp
void MqttHandler::handleAircraftOsd(const nlohmann::json& json) {
    // ... 解析 GPS、姿态等字段 ...

    // 新增: 解析飞行模式
    int modeCode = data.value("mode_code", 0);

    auto& flightData = device::FlightDataProvider::getInstance();
    flightData.updateFlightMode(modeCode);

    // 飞行模式变更时输出日志
    if (modeCode != lastModeCode) {
        logger_.info("✈️ 飞行模式变更: " + flightData.getFlightModeString());

        if (flightData.isReturningOrLanding()) {
            logger_.warning("⚠️ 无人机进入返航/降落状态，智能变焦拍照将暂停");
        }
        lastModeCode = modeCode;
    }
}
```

### 4. 在 LiveStreamTask 中添加飞行状态检查 (LiveStreamTask.cpp)

```cpp
// 3b. 变焦拍照策略处理（如果启用）
if (zoomCaptureEnabled_ && zoomCaptureStrategy_) {
    auto& flightData = device::FlightDataProvider::getInstance();

    // ⚠️ 检查飞行状态：返航/降落时跳过变焦拍照
    if (flightData.isReturningOrLanding()) {
        // 输出一次警告日志
        static bool rthWarningLogged = false;
        if (!rthWarningLogged) {
            logger_.warning("⚠️ 无人机正在返航/降落，暂停智能变焦拍照");
            rthWarningLogged = true;
        }
        // 跳过策略处理
    } else {
        // 正常处理变焦拍照策略
        // ...
    }
}
```

## 🎯 设计亮点

### 1. 最小侵入性修改

- 只在 `FlightDataProvider` 中添加新字段，不影响现有的 GPS/姿态数据处理
- 通过简单的 `if-else` 分支控制变焦拍照逻辑

### 2. 日志可追溯性

- 飞行模式变更时立即输出日志
- 进入返航状态时输出警告，便于事后排查

### 3. 易于扩展

- `FlightMode` 枚举包含所有 DJI 定义的飞行模式
- 可以轻松添加 `isReadyForAlgorithmTask()` 等更精细的判断方法

## 📌 面试考点

### Q: 为什么使用枚举而不是直接比较 int 值？

**A**:

1. **类型安全**: `enum class` 强类型，不能隐式转换为 int
2. **可读性**: `FlightMode::kAutoRth` 比 `9` 更清晰
3. **可维护性**: 如果 DJI 更改了枚举值，只需修改一处
4. **IDE 支持**: 自动补全和编译期检查

### Q: 为什么用 static bool 控制日志输出？

**A**:
避免日志刷屏。返航状态可能持续几分钟，每帧都输出警告会产生大量重复日志。使用 `static bool` 确保只输出一次警告。

### Q: 这种设计是否符合 SOLID 原则？

**A**:

- **SRP (单一职责)**: `FlightDataProvider` 只负责存储和提供飞行数据
- **OCP (开闭原则)**: 添加新的飞行模式只需扩展枚举，不需要修改现有代码
- **ISP (接口隔离)**: 提供了 `isReturningOrLanding()` 和 `isReadyForAlgorithmTask()` 两个具体的查询方法

## ✅ 测试验证

### 预期行为

1. **正常航线飞行时**

   - mode_code = 5
   - 智能变焦拍照正常触发

2. **无人机返航时**

   - mode_code = 9
   - 日志输出: `✈️ 飞行模式变更: 自动返航`
   - 日志输出: `⚠️ 无人机进入返航/降落状态，智能变焦拍照将暂停`
   - 智能变焦拍照暂停

3. **无人机降落时**
   - mode_code = 10 或 11
   - 智能变焦拍照暂停

### 验证方法

查看运行日志，确认：

- OSD 数据中 mode_code 被正确解析
- 飞行模式变更时有日志输出
- 返航状态下变焦拍照不触发
