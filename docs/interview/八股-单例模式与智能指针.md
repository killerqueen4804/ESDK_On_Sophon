## 📌 核心概念

### 单例模式 (Singleton Pattern)

确保一个类只有一个实例,并提供全局访问点。

### shared_ptr 自定义删除器

允许自定义 shared_ptr 销毁对象的方式,而不是默认的 delete。

## 🎯 项目实战案例

### 场景 1: MqttClient 单例模式

```cpp
// include/esdk_sophon/Mqtt/MqttClient.h
namespace esdk_sophon {
namespace mqtt {

class MqttClient {
public:
    // ✅ Meyers 单例 (C++11推荐)
    static MqttClient& getInstance() {
        static MqttClient instance;  // 线程安全初始化
        return instance;
    }

    // 禁止拷贝和赋值
    MqttClient(const MqttClient&) = delete;
    MqttClient& operator=(const MqttClient&) = delete;

private:
    // 私有构造函数
    MqttClient() = default;
    ~MqttClient() = default;
};

}  // namespace mqtt
}  // namespace esdk_sophon
```

### 场景 2: 单例与 shared_ptr 的结合

```cpp
// tests/test_task_basic.cpp
// 问题: TaskService 需要 shared_ptr<MqttClient>,但 MqttClient 是单例

// ❌ 错误做法: 直接传 nullptr
std::shared_ptr<MqttClient> mqttPtr = nullptr;
auto service = std::make_shared<TaskService>(mqttPtr);  // 运行时错误!

// ❌ 错误做法: 创建 shared_ptr 指向单例
auto mqttPtr = std::shared_ptr<MqttClient>(&MqttClient::getInstance());
// 析构时会调用 delete &getInstance(),导致 double free!

// ✅ 正确做法: 使用自定义删除器
auto mqttPtr = std::shared_ptr<MqttClient>(
    &MqttClient::getInstance(),    // 原始指针
    [](MqttClient*) {}             // 空删除器 (什么都不做)
);

// 现在可以安全使用了
auto service = std::make_shared<TaskService>(mqttPtr);
```

## 📊 单例模式演进

### 演进 1: 懒汉式 (非线程安全)

```cpp
// ❌ C++98 懒汉式 - 线程不安全
class Singleton {
public:
    static Singleton* getInstance() {
        if (instance == nullptr) {
            instance = new Singleton();  // ← 多线程问题!
        }
        return instance;
    }

private:
    static Singleton* instance;
    Singleton() = default;
};

Singleton* Singleton::instance = nullptr;

// 问题: 两个线程同时调用,可能创建两个实例
```

### 演进 2: 双检查锁 (DCL)

```cpp
// ⚠️ C++98 双检查锁 - 复杂且容易出错
class Singleton {
public:
    static Singleton* getInstance() {
        if (instance == nullptr) {                    // 第一次检查
            std::lock_guard<std::mutex> lock(mutex);
            if (instance == nullptr) {                // 第二次检查
                instance = new Singleton();
            }
        }
        return instance;
    }

private:
    static Singleton* instance;
    static std::mutex mutex;
};

// 问题: 代码复杂,容易写错
```

### 演进 3: Meyers 单例 (推荐)

```cpp
// ✅ C++11 Meyers 单例 - 简洁且线程安全
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // C++11保证线程安全
        return instance;
    }

    // 删除拷贝和赋值
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

private:
    Singleton() = default;
    ~Singleton() = default;
};

// 优点:
// 1. 代码简洁
// 2. 线程安全 (C++11标准保证)
// 3. 延迟初始化 (第一次调用时才创建)
// 4. 自动销毁 (程序结束时自动调用析构)
```

## 🎓 面试要点

### 高频问题 1: C++11 的 Meyers 单例为什么是线程安全的?

**标准答案**:

C++11 标准规定: **局部静态变量的初始化是线程安全的**。

```cpp
static Singleton& getInstance() {
    static Singleton instance;  // ← 只会初始化一次,且线程安全
    return instance;
}
```

**编译器实现原理** (大致等价):

```cpp
static Singleton& getInstance() {
    // 编译器生成的隐式代码
    static bool initialized = false;
    static std::aligned_storage<sizeof(Singleton)> storage;
    static std::mutex hidden_mutex;  // 隐式互斥锁

    if (!initialized) {
        std::lock_guard<std::mutex> lock(hidden_mutex);  // 加锁
        if (!initialized) {
            new (&storage) Singleton();  // placement new
            initialized = true;
        }
    }

    return *reinterpret_cast<Singleton*>(&storage);
}
```

**关键点**:

1. **首次调用时初始化** (lazy initialization)
2. **编译器自动加锁** (无需手动写 mutex)
3. **只初始化一次** (初始化后 initialized = true)

### 高频问题 2: shared_ptr 的自定义删除器有什么用?

**标准答案**:

shared_ptr 默认使用 `delete` 销毁对象,但有些资源不是用 `new` 分配的,需要自定义删除方式。

**场景 1: 文件句柄**

```cpp
// FILE* 需要用 fclose,而不是 delete
std::shared_ptr<FILE> filePtr(
    fopen("file.txt", "r"),
    [](FILE* f) {
        if (f) fclose(f);  // 使用 fclose 而非 delete
    }
);

// 作用域结束时自动关闭文件
```

**场景 2: 数组**

```cpp
// new[] 分配的数组需要用 delete[],而不是 delete
std::shared_ptr<int> arrayPtr(
    new int[10],
    [](int* p) { delete[] p; }  // 使用 delete[]
);

// 或者使用 std::default_delete<int[]>
std::shared_ptr<int> arrayPtr2(new int[10], std::default_delete<int[]>());
```

**场景 3: 单例对象**

```cpp
// 单例对象不应该被 delete
std::shared_ptr<Singleton> singletonPtr(
    &Singleton::getInstance(),
    [](Singleton*) {}  // 空删除器,什么都不做
);

// 引用计数归零时,调用空删除器,不会 delete 单例
```

**场景 4: 特殊释放逻辑**

```cpp
// 设备需要先断开连接再释放
std::shared_ptr<Device> devicePtr(
    new Device(),
    [](Device* d) {
        d->disconnect();  // 先断开连接
        delete d;         // 再释放内存
    }
);
```

### 高频问题 3: 为什么单例的 shared_ptr 需要空删除器?

**标准答案**:

```cpp
// ❌ 错误: 会尝试 delete 单例对象
auto ptr1 = std::shared_ptr<Singleton>(&Singleton::getInstance());

// 当 ptr1 引用计数归零时,会调用默认删除器:
delete &Singleton::getInstance();
// ← 这是未定义行为! 单例对象是局部静态变量,不能 delete

// 可能导致:
// 1. double free (程序结束时再次销毁单例)
// 2. segmentation fault
// 3. 其他未定义行为
```

```cpp
// ✅ 正确: 使用空删除器
auto ptr2 = std::shared_ptr<Singleton>(
    &Singleton::getInstance(),
    [](Singleton*) {}  // 什么都不做
);

// 引用计数归零时,调用空删除器:
[](Singleton* p) {}(p);  // 什么都不做,不会 delete
// ✅ 单例对象仍然存活,直到程序结束才销毁
```

### 高频问题 4: 单例模式有哪些常见实现方式?

**标准答案**:

| 实现方式        | 优点                         | 缺点             | 推荐度 |
| --------------- | ---------------------------- | ---------------- | ------ |
| **懒汉式**      | 延迟初始化                   | 线程不安全       | ❌     |
| **饿汉式**      | 线程安全                     | 不支持延迟初始化 | ⚠️     |
| **双检查锁**    | 线程安全 + 延迟初始化        | 代码复杂,易出错  | ⚠️     |
| **Meyers 单例** | 简洁 + 线程安全 + 延迟初始化 | 需要 C++11       | ✅     |

**代码示例**:

```cpp
// 1. 懒汉式 (Lazy) - 线程不安全
class Singleton {
    static Singleton* instance;
public:
    static Singleton* getInstance() {
        if (!instance) instance = new Singleton();  // ❌ 竞态条件
        return instance;
    }
};

// 2. 饿汉式 (Eager) - 线程安全但不支持延迟初始化
class Singleton {
    static Singleton instance;  // 程序启动时初始化
public:
    static Singleton& getInstance() { return instance; }
};
Singleton Singleton::instance;

// 3. 双检查锁 (DCL) - 复杂
class Singleton {
    static Singleton* instance;
    static std::mutex mtx;
public:
    static Singleton* getInstance() {
        if (!instance) {
            std::lock_guard<std::mutex> lock(mtx);
            if (!instance) instance = new Singleton();
        }
        return instance;
    }
};

// 4. Meyers单例 (推荐) - 简洁且线程安全
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // ✅ C++11保证线程安全
        return instance;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() = default;
};
```

### 高频问题 5: 单例模式有什么缺点?

**标准答案**:

**1. 全局状态**

```cpp
// 单例是全局状态,违反了依赖注入原则
void foo() {
    auto& client = MqttClient::getInstance();  // 隐式依赖
    // 难以测试,难以Mock
}

// 更好的设计: 依赖注入
void foo(MqttClient& client) {  // 显式依赖
    // 容易测试,容易Mock
}
```

**2. 难以测试**

```cpp
// 单例在测试中难以重置状态
TEST(MyTest, Test1) {
    auto& s = Singleton::getInstance();
    s.setValue(10);
}

TEST(MyTest, Test2) {
    auto& s = Singleton::getInstance();  // 还是同一个实例!
    // s.getValue() == 10  ← Test1的副作用
}
```

**3. 生命周期问题**

```cpp
// 单例的析构顺序不确定
class Logger {
    static Logger& getInstance() {
        static Logger instance;
        return instance;
    }
};

class Database {
    ~Database() {
        Logger::getInstance().log("DB关闭");  // ⚠️ Logger可能已销毁!
    }
};
```

**4. 违反单一职责原则**

```cpp
// 单例既要管理自己的业务逻辑,又要管理实例创建
class Singleton {
public:
    static Singleton& getInstance() { /* 管理实例 */ }
    void doSomething() { /* 业务逻辑 */ }
};
```

## 💡 实战技巧

### 技巧 1: 使用 std::call_once 实现线程安全单例

```cpp
class Singleton {
private:
    static std::once_flag initFlag;
    static Singleton* instance;

public:
    static Singleton& getInstance() {
        std::call_once(initFlag, []() {
            instance = new Singleton();
        });
        return *instance;
    }
};

std::once_flag Singleton::initFlag;
Singleton* Singleton::instance = nullptr;
```

### 技巧 2: 禁止拷贝和移动

```cpp
class Singleton {
public:
    // 删除拷贝
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    // 删除移动 (C++11)
    Singleton(Singleton&&) = delete;
    Singleton& operator=(Singleton&&) = delete;
};
```

### 技巧 3: 单例的智能指针包装

```cpp
// 提供获取 shared_ptr 的接口
class MqttClient {
public:
    static MqttClient& getInstance() {
        static MqttClient instance;
        return instance;
    }

    // 获取 shared_ptr (使用空删除器)
    static std::shared_ptr<MqttClient> getSharedInstance() {
        return std::shared_ptr<MqttClient>(
            &getInstance(),
            [](MqttClient*) {}
        );
    }
};

// 使用
auto mqttPtr = MqttClient::getSharedInstance();
```

## 📝 总结

### 核心要点

1. ✅ Meyers 单例是现代 C++的推荐实现
2. ✅ C++11 保证局部静态变量初始化的线程安全

4. ⚠️ 单例是全局状态,应谨慎使用

### 面试答题模板

**Q: 如何实现线程安全的单例模式?**

**A**: 在 C++11 中,使用 Meyers 单例是最简洁的实现:

```cpp
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // C++11保证线程安全
        return instance;
    }
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
private:
    Singleton() = default;
};
```

**原理**: C++11 标准保证局部静态变量的初始化是线程安全的,编译器会自动加锁保证只初始化一次。

**项目应用**: 在 DJI ESDK 项目中,MqttClient 使用 Meyers 单例确保全局只有一个 MQTT 连接。在测试代码中,通过 shared_ptr 的自定义删除器将单例包装为智能指针,避免析构时错误地 delete 单例对象。
