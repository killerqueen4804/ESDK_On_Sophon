## 📌 核心概念

**静态工厂方法 (Static Factory Method)** 是一种创建对象的设计模式,通过静态方法而非构造函数创建对象。

### 为什么需要?

构造函数的局限性:

1. **名称固定**: 必须与类名相同,无法描述创建方式
2. **返回类型固定**: 只能返回当前类
3. **重载歧义**: 参数类型相同时容易混淆

## 🎯 项目实战案例

### 场景: TaskConfig 的多种创建方式

```cpp
// include/esdk_sophon/task/TaskTypes.h
struct TaskConfig {
    std::string taskId;
    TaskType type;
    std::vector<EventType> eventTypes;
    // ... 其他字段

    // ✅ 静态工厂方法: 从JSON创建
    static TaskConfig fromJson(const nlohmann::json& json);

    // 如果用构造函数:
    // ❌ TaskConfig(const nlohmann::json& json);  // 语义不够清晰
};

// src/task/TaskTypes.cpp
TaskConfig TaskConfig::fromJson(const nlohmann::json& json) {
    TaskConfig config;
    config.taskId = std::to_string(json.at("taskID").get<int>());
    config.type = (json.value("dataSource", "live") == "live")
        ? TaskType::DETECTION_LIVESTREAM
        : TaskType::DETECTION_MEDIAFILE;

    // 解析事件类型数组
    if (json.contains("type") && json["type"].is_array()) {
        for (const auto& typeObj : json["type"]) {
            EventType eventType;
            eventType.id = typeObj.value("id", 0);
            eventType.mainType = typeObj.value("main_type", 0);
            eventType.eventDescribe = typeObj.value("name", "");
            config.eventTypes.push_back(eventType);
        }
    }

    return config;
}

// 使用示例
auto mqttMessage = /* MQTT消息的JSON */;
TaskConfig config = TaskConfig::fromJson(mqttMessage);  // 语义清晰
```

### 实际使用场景

```cpp
// src/Mqtt/MqttHandler.cpp - MQTT消息处理
void MqttHandler::handleAlgorithmEnable(const nlohmann::json& data) {
    // ✅ 清晰的语义: 从MQTT消息创建任务配置

    // 启动任务
    bool success = taskManager_.startTask(config);
```

## 📊 对比分析

### 构造函数 vs 静态工厂方法

| 特性         | 构造函数             | 静态工厂方法         |
| ------------ | -------------------- | -------------------- |
| **名称**     | 必须与类名相同       | 可以有清晰的语义名称 |
| **返回类型** | 只能返回当前类       | 可以返回子类或派生类 |
| **实例控制** | 每次调用都创建新对象 | 可以返回缓存的对象   |
| **参数歧义** | 重载可能产生歧义     | 不同名称避免歧义     |
| **IDE 提示** | 自动提示构造函数     | 需要知道方法名       |

### 实际代码对比

```cpp
// ❌ 使用构造函数 (语义不清晰)
class TaskConfig {
public:
    TaskConfig(const nlohmann::json& json);        // 从JSON?
    TaskConfig(const std::string& configFile);     // 从文件?
    TaskConfig(int taskId);                        // 从数据库?
    // 看参数类型才知道做什么
};

// 使用时不够清晰
TaskConfig config1(jsonData);     // 这是从JSON创建吗?
TaskConfig config2("config.json"); // 这是从文件创建吗?

// ✅ 使用静态工厂方法 (语义清晰)
class TaskConfig {
public:
    static TaskConfig fromJson(const nlohmann::json& json);
    static TaskConfig fromFile(const std::string& configFile);
    static TaskConfig fromDatabase(int taskId);
    // 方法名直接说明了来源
};

// 使用时一目了然
TaskConfig config1 = TaskConfig::fromJson(jsonData);     // 从JSON创建
TaskConfig config2 = TaskConfig::fromFile("config.json"); // 从文件创建
TaskConfig config3 = TaskConfig::fromDatabase(1001);     // 从数据库创建
```

## 🎓 面试要点

### 高频问题 1: 静态工厂方法有什么优势?

**标准答案**:

**1. 语义清晰**

```cpp
// 方法名可以描述对象的创建方式
TaskConfig::fromJson(json)    // 清楚知道是从JSON创建
TaskConfig::fromDatabase(id)  // 清楚知道是从数据库创建
```

**2. 返回类型灵活**

```cpp
// 可以返回子类 (工厂模式的基础)
class TaskManager {
public:
    static std::unique_ptr<ITask> createTask(TaskType type) {
        switch (type) {
            case TaskType::DETECTION_LIVESTREAM:
                return std::make_unique<LiveStreamTask>();
            case TaskType::DETECTION_MEDIAFILE:
                return std::make_unique<MediaFileTask>();
            default:
                return nullptr;
        }
    }
};

// 返回的是 ITask 接口,但实际是具体的子类
auto task = TaskManager::createTask(TaskType::DETECTION_LIVESTREAM);
// task 的实际类型是 LiveStreamTask,但使用 ITask 接口
```

**3. 实例控制**

```cpp
// 可以返回缓存的对象,实现对象池
class TaskConfig {
private:
    static std::map<int, TaskConfig> configCache_;

public:
    static TaskConfig& fromDatabase(int taskId) {
        // 如果缓存中有,直接返回
        auto it = configCache_.find(taskId);
        if (it != configCache_.end()) {
            return it->second;
        }

        // 否则从数据库加载并缓存
        TaskConfig config = loadFromDB(taskId);
        configCache_[taskId] = config;
        return configCache_[taskId];
    }
};
```

**4. 避免参数歧义**

```cpp
// ❌ 构造函数重载容易混淆
class TaskConfig {
public:
    TaskConfig(int taskId);      // 从任务ID创建
    TaskConfig(int algorithmId); // 从算法ID创建?  ← 编译错误!
    // 两个参数类型相同,无法重载
};

// ✅ 静态工厂方法避免歧义
class TaskConfig {
public:
    static TaskConfig fromTaskId(int id);
    static TaskConfig fromAlgorithmId(int id);
    // 方法名不同,参数类型相同也没问题
};
```

### 高频问题 2: 静态工厂方法有什么缺点?

**标准答案**:

**1. 无法继承**

```cpp
class Base {
public:
    static Base create() { return Base(); }
};

class Derived : public Base {
    // 无法继承 static 方法
    // static Base create();  // 这不是重写,而是隐藏
};
```

**2. 发现性差**

```cpp
// IDE 自动提示构造函数
TaskConfig config(/* IDE会提示参数 */);

// 静态工厂方法需要知道方法名
TaskConfig config = TaskConfig::from/* 需要手动输入 */;
```

**3. 命名不统一**

```cpp
// 常见的命名约定 (但不是强制的)
from*      // TaskConfig::fromJson()
of*        // Integer::of(10)  (Java风格)
valueOf*   // Integer::valueOf(10)  (Java风格)
getInstance*  // Singleton::getInstance()
create*    // TaskManager::createTask()
```

### 高频问题 3: Java 和 C++的静态工厂方法有什么区别?

**标准答案**:

**Java 中的静态工厂方法**:

```java
// Java 非常推崇静态工厂方法
Integer i1 = Integer.valueOf(10);  // 静态工厂方法
Integer i2 = new Integer(10);      // 构造函数 (已废弃)

List<String> list = Collections.emptyList();  // 静态工厂方法
```

**C++ 中的静态工厂方法**:

```cpp
// C++ 更倾向于使用构造函数
std::string s1("hello");        // 直接构造
auto s2 = std::string("hello"); // 也可以

// 但现代 C++17 推荐使用静态工厂方法提升可读性
TaskConfig config = TaskConfig::fromJson(json);  // 推荐
```

**原因**:

- **Java**: 对象必须在堆上分配,静态工厂方法可以控制对象创建
- **C++**: 对象可以在栈上分配,构造函数更直接高效

### 高频问题 4: 什么时候应该使用静态工厂方法?

**标准答案**:

**✅ 应该使用的场景**:

1. **创建方式有多种**

   ```cpp
   TaskConfig::fromJson(json);
   TaskConfig::fromFile(filename);
   TaskConfig::fromDatabase(id);
   ```

2. **需要返回子类**

   ```cpp
   ITask* createTask(TaskType type);  // 返回 LiveStreamTask 或 MediaFileTask
   ```

3. **需要对象池/缓存**

   ```cpp
   static TaskConfig& getInstance(int id);  // 返回缓存的配置
   ```

4. **构造函数参数容易混淆**
   ```cpp
   fromTaskId(123);
   fromAlgorithmId(456);
   ```

**❌ 不应该使用的场景**:

1. **只有一种简单的创建方式**

   ```cpp
   // 直接用构造函数即可
   std::string name("Alice");
   ```

2. **性能关键路径**
   ```cpp
   // 构造函数可以被编译器优化 (RVO, 移动语义)
   MyClass obj(arg1, arg2);
   ```

## 💡 实战技巧

### 技巧 1: 结合 private 构造函数

```cpp
class TaskConfig {
public:
    // 公开静态工厂方法
    static TaskConfig fromJson(const nlohmann::json& json);

private:
    // 私有构造函数,强制使用工厂方法
    TaskConfig() = default;
};
```

### 技巧 2: 返回智能指针

```cpp
class TaskManager {
public:
    // 返回 unique_ptr,所有权清晰
    static std::unique_ptr<ITask> createTask(const TaskConfig& config) {
        if (config.type == TaskType::DETECTION_LIVESTREAM) {
            return std::make_unique<LiveStreamTask>(config);
        }
        return std::make_unique<MediaFileTask>(config);
    }
};
```

### 技巧 3: 错误处理

```cpp
class TaskConfig {
public:
    static TaskConfig fromJson(const nlohmann::json& json) {
        // 验证必需字段
        if (!json.contains("taskID")) {
            throw std::invalid_argument("缺少必需字段: taskID");
        }

        TaskConfig config;
        config.taskId = std::to_string(json.at("taskID").get<int>());
        // ...
        return config;
    }
};
```

## 🔗 相关知识点

- **工厂模式**: 静态工厂方法是工厂模式的基础
- **构建器模式**: 复杂对象的另一种创建方式
- **单例模式**: getInstance() 就是静态工厂方法
- **对象池模式**: 静态工厂方法可以实现对象复用

## 📝 总结

### 核心要点

1. ✅ 静态工厂方法提供清晰的语义
2. ✅ 可以返回子类,实现多态
3. ✅ 可以控制对象创建,实现缓存
4. ⚠️ 但发现性较差,需要知道方法名

### 面试答题模板

**Q: 什么是静态工厂方法?**

**A**: 静态工厂方法是一种对象创建模式,通过类的静态方法而非构造函数创建对象。

**优点**:

1. 方法名可以描述创建方式,语义清晰
2. 可以返回子类,实现多态
3. 可以控制对象创建,实现缓存和对象池
4. 避免构造函数重载的参数歧义

**缺点**:

1. 无法被子类继承
2. IDE 不会自动提示
3. 命名规范不统一

**项目应用**: 在 DJI ESDK 项目中,我使用 `TaskConfig::fromJson()` 静态工厂方法从 MQTT 消息创建任务配置,相比构造函数更清晰,代码可读性更好。
