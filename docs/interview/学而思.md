## 策略模式和工厂模式

### 相似之处

1.  **都依赖于接口（或抽象类）和多态：**

    - **简单工厂：** 有一个产品接口（`Product`）和多个具体产品类（`ConcreteProductA`, `ConcreteProductB`）。工厂方法返回的是产品接口类型。
    - **策略模式：** 有一个策略接口（`Strategy`）和多个具体策略类（`ConcreteStrategyA`, `ConcreteStrategyB`）。上下文（`Context`）持有的也是策略接口类型。
    - **共同点：** 客户端代码（或上下文）与具体的实现类解耦，只与接口打交道。

2.  **都涉及“选择”：**
    - **简单工厂：** 工厂根据某种输入（例如类型字符串或枚举）“选择”并创建对应的具体产品对象。
    - **策略模式：** 客户端（或上下文的配置者）根据需要“选择”一个具体的策略对象，并将其设置给上下文，上下文随后使用这个策略来执行行为。
    - **共同点：** 都有一个机制来决定使用哪个具体实现。

### 根本区别

尽管有上述相似之处，但它们的**目的**和**关注点**完全不同。

#### 1. 简单工厂模式 (Simple Factory Pattern)

- **目的：** **创建对象。** 它负责根据客户端的请求，集中创建不同类型的对象。它将对象的创建逻辑封装在一个工厂类中，从而将客户端代码与具体产品类的实例化过程解耦。
- **关注点：** **“我要哪个对象？”**
- **角色：**
  - **工厂 (Factory)：** 负责创建所有具体产品的实例。
  - **产品接口 (Product Interface/Abstract Class)：** 定义所有产品共有的接口。
  - **具体产品 (Concrete Product)：** 实现产品接口的具体产品类。
- **何时使用：** 当你需要在代码中创建一系列相关或相似的对象，并且希望将创建逻辑集中管理，避免客户端直接依赖具体产品类时。
- **缺点：** 不符合“开闭原则”（Open/Closed Principle）。每当增加新的产品类型时，都需要修改工厂类中的创建逻辑。因此，它不是 GoF（Gang of Four）设计模式之一，更像是一种编程习惯或技巧。

**简单工厂的例子：**
假设你有一个图形绘制工具，可以创建圆形、方形、三角形。

```java
// 产品接口
interface Shape {
    void draw();
}

// 具体产品
class Circle implements Shape {
    public void draw() { System.out.println("Drawing Circle"); }
}
class Square implements Shape {
    public void draw() { System.out.println("Drawing Square"); }
}

// 简单工厂
class ShapeFactory {
    public static Shape createShape(String type) {
        if ("circle".equalsIgnoreCase(type)) {
            return new Circle();
        } else if ("square".equalsIgnoreCase(type)) {
            return new Square();
        }
        return null; // 或者抛出异常
    }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        Shape circle = ShapeFactory.createShape("circle"); // 工厂创建对象
        circle.draw();

        Shape square = ShapeFactory.createShape("square");
        square.draw();
    }
}
```

客户端关心的是**获取一个什么类型的对象**。

#### 2. 策略模式 (Strategy Pattern)

- **目的：** **封装算法/行为。** 它定义了一系列算法，并将每个算法封装起来，使它们可以相互替换。策略模式让算法的变化独立于使用算法的客户端。
- **关注点：** **“我应该如何执行这个行为？”**
- **角色：**
  - **上下文 (Context)：** 维护一个对策略对象的引用，并委托策略对象执行算法。
  - **策略接口 (Strategy Interface/Abstract Class)：** 定义所有具体策略类共有的接口。
  - **具体策略 (Concrete Strategy)：** 实现策略接口的具体算法类。
- **何时使用：** 当一个对象有多种行为，并且这些行为可以在运行时根据不同的条件进行切换时。它符合“开闭原则”，增加新的策略不需要修改上下文。
- **优点：** 提供了算法的运行时切换能力，避免了多重条件判断语句，使得代码更灵活、可维护。

**策略模式的例子：**
假设一个订单系统，有多种支付方式（信用卡、PayPal、现金）。

```java
// 策略接口
interface PaymentStrategy {
    void pay(double amount);
}

// 具体策略
class CreditCardPayment implements PaymentStrategy {
    private String cardNumber;
    public CreditCardPayment(String cn) { this.cardNumber = cn; }
    public void pay(double amount) { System.out.println("Paying " + amount + " with Credit Card " + cardNumber); }
}
class PayPalPayment implements PaymentStrategy {
    private String email;
    public PayPalPayment(String email) { this.email = email; }
    public void pay(double amount) { System.out.println("Paying " + amount + " with PayPal " + email); }
}

// 上下文
class ShoppingCart {
    private PaymentStrategy paymentStrategy;
    private double totalAmount;

    public void setPaymentStrategy(PaymentStrategy strategy) {
        this.paymentStrategy = strategy;
    }

    public void addItem(double price) {
        this.totalAmount += price;
    }

    public void checkout() {
        if (paymentStrategy == null) {
            System.out.println("No payment strategy selected.");
            return;
        }
        paymentStrategy.pay(totalAmount); // 委托策略执行行为
        totalAmount = 0; // 支付后清零
    }
}

// 客户端
public class Client {
    public static void main(String[] args) {
        ShoppingCart cart = new ShoppingCart();
        cart.addItem(100.0);
        cart.addItem(50.0);

        // 选择并设置策略
        cart.setPaymentStrategy(new CreditCardPayment("1234-5678-9012-3456"));
        cart.checkout(); // 执行支付行为

        cart.addItem(75.0);
        cart.setPaymentStrategy(new PayPalPayment("user@example.com"));
        cart.checkout(); // 切换策略，再次执行支付行为
    }
}
```

客户端关心的是**如何执行一个行为**，并且可以在运行时切换执行方式。

### 总结对比

| 特性         | 简单工厂模式                      | 策略模式                             |
| :----------- | :-------------------------------- | :----------------------------------- |
| **核心目的** | **创建**对象                      | **封装和切换**算法/行为              |
| **关注点**   | “我要哪个**对象**？”              | “我应该**如何**执行这个**行为**？”   |
| **运行时**   | 通常在对象**创建时**决定一次      | 允许在对象**生命周期内**动态切换行为 |
| **职责**     | 集中对象的实例化逻辑              | 封装一系列可互换的算法               |
| **O/C 原则** | 通常**不符合** (增加产品需改工厂) | **符合** (增加策略不需改上下文)      |
| **角色**     | 工厂、产品接口、具体产品          | 上下文、策略接口、具体策略           |

所以，当你感觉它们相似时，可能是因为它们都使用了多态来处理不同的实现。但它们的**意图**是根本的区别：简单工厂是关于**“生产什么”**，而策略模式是关于**“怎么做”**。

简单工厂解决的是“谁来创建对象”的问题，而策略模式解决的是“如何执行某个操作”的问题。理解了这一点，你就能清晰地区分它们了。

**思：**工厂模式注重的是每个功能都有一个类去实现，而策略模式则是每个功能可能会多个实现的方式，注重于一个功能会有不同的实现，比如超市收现金会有打折、满减等活动，打折、满减分别由不同的类实现，但是他们都是为功能“收现金”服务的。

## 类型别名 (Type Alias)

`using CommandHandler = std::function<void(const nlohmann::json&)>;` 这行代码在 C++ 中定义了一个 **类型别名 (Type Alias)**。

让我们分解一下它的含义：

1.  **`using CommandHandler = ...;`**

    - `using` 是 C++11 引入的一种创建类型别名的方式，它与 `typedef` 类似，但更现代且在模板中更易读。
    - `CommandHandler` 是你为这个新类型起的别名。从名字可以看出，它旨在表示一个“命令处理器”。

2.  **`std::function`**

    - 这是 C++ 标准库 `<functional>` 头文件中提供的一个模板类。
    - 它是一个**通用多态函数包装器**。这意味着 `std::function` 可以存储、复制和调用任何符合其指定签名的**可调用对象 (Callable Object)**。可调用对象包括：
      - 普通函数指针
      - Lambda 表达式
      - 函数对象 (Functors)
      - `std::bind` 的结果
      - 类成员函数指针（需要绑定到特定对象）

3.  **`<void(const nlohmann::json&)>`**
    - 这是 `std::function` 的模板参数，它定义了它所能包装的函数的**签名 (Signature)**。
    - `void`: 表示这个函数不返回任何值。
    - `(const nlohmann::json&)`: 表示这个函数接受一个参数，这个参数是 `nlohmann::json` 类型的**常量引用**。`nlohmann::json` 是一个流行的 C++ JSON 库，用于处理 JSON 数据。使用常量引用 (`const &`) 可以避免不必要的数据拷贝，提高效率。

**综合起来，这行代码的意思是：**

`CommandHandler` 现在是一个新的类型名称，它代表着任何**不返回任何值 (void)**，并且接受一个**`const nlohmann::json&` 类型参数**的可调用对象（例如函数、lambda 表达式或绑定后的成员函数）。

**在你的 `MqttHandler` 代码中的作用：**

这行代码的目的是为了实现一种**策略模式**或**命令模式**的变体，用于根据接收到的 MQTT 指令的 `method` 字段来路由到不同的处理函数。

在 `MqttHandler` 中，你会看到：

```cpp
std::map<std::string, CommandHandler> commandHandlers_;
```

这个 `commandHandlers_` 是一个 `std::map`，它的键是 `std::string` (例如，MQTT 指令中的 "method" 字段，如 "device_algorithm_sync")，它的值就是 `CommandHandler` 类型。

在 `initCommandHandlers()` 方法中，你会将不同的具体处理函数（例如 `handleAlgorithmSync`、`handleAlgorithmEnable` 等）绑定到这个 `map` 中：

```cpp
void MqttHandler::initCommandHandlers() {
    commandHandlers_["device_algorithm_sync"] = std::bind(&MqttHandler::handleAlgorithmSync, this, std::placeholders::_1);
    commandHandlers_["device_algorithm_enable"] = std::bind(&MqttHandler::handleAlgorithmEnable, this, std::placeholders::_1);
    // ... 其他指令
}
```

（注意：这里使用了 `std::bind` 来将成员函数绑定到 `this` 对象，并用 `std::placeholders::_1` 表示第一个参数将由调用者提供。）

当 `MqttHandler` 收到一个云端指令时，它会解析出 `method` 字段，然后通过这个 `map` 查找对应的 `CommandHandler`，并调用它来处理数据：

```cpp
void MqttHandler::handleServiceCommand(const nlohmann::json& json) {
    std::string method = json.at("method").get<std::string>();
    auto it = commandHandlers_.find(method);
    if (it != commandHandlers_.end()) {
        it->second(json.at("data")); // 调用找到的处理器，传入指令的data部分
    } else {
        // 未知指令处理
    }
}
```

**好处：**

- **解耦：** `handleServiceCommand` 函数不需要知道每个具体指令是如何处理的，它只知道如何查找并调用一个 `CommandHandler`。
- **扩展性：** 添加新的指令处理函数时，只需要实现新的 `void(const nlohmann::json&)` 签名的成员函数，并在 `initCommandHandlers()` 中将其注册到 `commandHandlers_` 中即可，无需修改 `handleServiceCommand` 的逻辑。
- **代码整洁：** 避免了大量的 `if-else if` 或 `switch` 语句来判断指令类型。

**思：**作用感觉像是对函数也做了一种泛化

```c++
void MqttHandler::initCommandHandlers() {
    logger_.debug("初始化指令处理函数映射表...");

    // 使用lambda表达式注册处理函数

    // 1. 算法同步(启动任务)
    commandHandlers_["device_algorithm_sync"] =
        [this](const nlohmann::json& data) {
            handleAlgorithmSync(data);
        };

    // 2. 启用算法
    commandHandlers_["device_algorithm_enable"] =
        [this](const nlohmann::json& data) {
            handleAlgorithmEnable(data);
        };

    // 3. 关闭算法(停止任务)
    commandHandlers_["device_algorithm_disable"] =
        [this](const nlohmann::json& data) {
            handleAlgorithmDisable(data);
        };

    // 4. 任务结束
    commandHandlers_["device_task_end"] =
        [this](const nlohmann::json& data) {
            handleTaskEnd(data);
        };

    // 5. 设备重启
    commandHandlers_["device_reboot"] =
        [this](const nlohmann::json& data) {
            handleReboot(data);
        };

    logger_.info("注册了 " + std::to_string(commandHandlers_.size()) +
                " 个指令处理函数");
}
```
