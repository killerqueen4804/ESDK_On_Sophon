## 第一章：项目整体架构概览

### 1.1 项目简介

**ESDK_On_Sophon** 是一个基于 DJI Edge-SDK 的无人机边缘计算项目，运行在算能（Sophon）SE7 微服务器上。

**核心功能**：

1. 接收云端任务指令（通过 MQTT）
2. 控制无人机获取图像/视频流（通过 DJI Edge-SDK）
3. 使用 AI 模型进行目标检测（PP-YOLOE 模型）
4. 将检测结果上报云端（事件推送）
5. 实时视频流推送（RTMP，可选）

**技术栈**：

- 语言：C++17
- 构建：CMake 3.10+
- AI 推理：FastDeploy + Sophon TPU
- 通信：MQTT (Qt5Mqtt) + HTTP (libcurl)
- 视频：FFmpeg + GStreamer
- SDK：DJI Edge-SDK

### 1.4 模块初始化顺序（来自 Application::initialize）

根据 `Application.cpp` 的实际代码，模块初始化顺序如下：

```cpp
// Application::initialize() 中的实际初始化顺序
bool Application::initialize() {
    // 步骤0: 初始化 DJI Edge-SDK（最优先！）
    auto rc = ESDKInit();

    // 步骤1: 初始化日志系统
    // Logger 是单例，已在 Application 构造函数中获取引用
    logger_.info("ESDK Sophon Application Starting");

    // 步骤2: 加载配置文件
    config_.load("config/config.json");

    // 步骤3: 跳过（TaskManager 需要 MQTT 先连接）

    // 步骤4: 初始化并连接 MqttClient
    mqttClient_.initialize();
    mqttClient_.connect();

    // 步骤4.5: 初始化 TaskManager
    taskManager_.initialize();  // 内部会创建 TaskService

    // 步骤5: 初始化并启动 MqttHandler
    mqttHandler_.initialize();  // 读取配置、构建 Topic
    mqttHandler_.start();       // 注册观察者、订阅 Topic

    // 注册信号处理函数（SIGINT、SIGTERM）
    registerSignalHandlers();

    return true;
}
```

```
                                  ▼                    │
                        ┌───────────────────┐          │
                        │ completeTask()    │          │
                        │                   │          │
                        │ 1. 推送分析结果   │          │
                        │ 2. 清理本地文件   │          │
                        │ 3. 恢复 DJI 设置  │          │
                        │ 4. 等待平台发送   │          │
                        │    algorithm_disable         │
                        └───────────────────┘          │
```

**📌 重要设计点**：

- `MediaFileTask` 收到 `device_task_end` 后**不立即停止**
- 因为飞机返航后，文件可能还在传输中
- 使用 `taskEnded_` 标志 + 60 秒超时机制判断文件是否传输完成
- 这是**多态**的典型应用：不同任务类型，`onTaskEnd()` 行为不同

## 📚 面试要点总结

### Q1: 请介绍一下这个项目的整体架构？

**标准答案**（基于实际代码）：

> 这是一个基于 DJI Edge-SDK 的无人机边缘计算项目，采用**分层架构**设计：
>
> 1. **入口层**（Application）：单例模式的应用程序协调器，负责按正确顺序初始化和关闭所有模块
> 2. **通信层**（MqttClient + MqttHandler）：MqttClient 封装 Paho MQTT 库，MqttHandler 实现消息路由
> 3. **任务管理层**（TaskManager）：使用工厂模式创建不同类型的任务（MediaFileTask、LiveStreamTask）
> 4. **业务编排层**（TaskService）：编排帧处理流程，调用检测器、构建事件、发布 MQTT
> 5. **视觉层**（DetectorFactory + IDetector）：工厂模式 + 策略模式，支持多种检测算法
> 6. **设备层**（DJI Edge-SDK 封装）：Liveview 获取视频流，MediaManager 监听文件
> 7. **基础设施层**（Core）：日志、配置、事件缓存等公共组件（全部是单例）
>
> **关键设计点**：
>
> - 大量使用单例模式，通过 `getInstance()` 获取全局唯一实例
> - MqttHandler 使用 `commandHandlers_` 映射表实现指令路由（类似命令模式）
> - MediaFileTask 使用生产者-消费者模式：DJI SDK 回调生产文件，工作线程消费处理
> - 任务结束时使用多态：`task->onTaskEnd()` 让不同任务类型有不同的结束行为

### Q2: 描述一下媒体文件分析的完整流程？

**标准答案**：

> 1. 平台发送 `device_algorithm_enable` 消息到 MQTT Topic
> 2. `MqttClient` 收到消息，通过观察者模式通知 `MqttHandler`
> 3. `MqttHandler::onMessageReceived()` 解析 JSON，根据 `method` 字段路由到 `handleAlgorithmEnable()`
> 4. `handleAlgorithmEnable()` 解析 `TaskConfig`，调用 `TaskManager::startTask()`
> 5. `TaskManager` 根据 `config.type` 使用工厂模式创建 `MediaFileTask`
> 6. `MediaFileTask::start()` 注册 DJI `MediaFilesObserver` 回调，创建工作线程和监控线程
> 7. 当 DJI SDK 检测到新文件，触发 `onMediaFileUpdate()` 回调，文件进入队列
> 8. 工作线程 `execute()` 从队列取出文件，调用 `processFile()` 处理
> 9. `processFile()` 解析 EXIF（GPS、航向），调用 `TaskService::processFrame()` 进行检测
> 10. `TaskService` 调用检测器，构建事件，通过 `publishEvent()` 发布到 MQTT

### Q3: 为什么 MediaFileTask 收到 `device_task_end` 后不立即停止？

**标准答案**：

> 这是 `MediaFileTask` 和 `LiveStreamTask` 的**关键差异**：
>
> - `LiveStreamTask` 是实时视频流，收到结束信号后可以立即停止
> - `MediaFileTask` 处理的是文件，飞机返航后文件可能还在传输中
>
> 所以 `MediaFileTask::onTaskEnd()` 只设置 `taskEnded_` 标志，由 `monitorLoop()` 监控线程检测：
>
> - 条件 1：`taskEnded_ == true`（航线已结束）
> - 条件 2：60 秒内没有收到新文件（文件传输完成）
>
> 两个条件都满足后，才调用 `completeTask()` 完成任务。这是**多态**的典型应用。

### Q4: 项目中使用了哪些设计模式？举例说明。

**标准答案**：

> 1. **单例模式**：`Logger::getInstance()`, `Config::getInstance()`, `Application::getInstance()`
>
>    - 保证全局唯一，方便跨模块访问
>    - 使用 Meyers 单例（局部静态变量），C++11 保证线程安全
>
> 2. **工厂模式**：`TaskManager::createTask()`, `DetectorFactory::createDetector()`
>
>    - 根据类型参数创建不同的具体对象
>    - 客户端不需要知道具体类名
>
> 3. **观察者模式**：`IMqttMessageObserver` 接口
>
>    - `MqttHandler` 实现接口，注册到 `MqttClient`
>    - 消息到达时 `MqttClient` 通知所有观察者
>
> 4. **策略模式**：`IDetector` 接口
>
>    - `PPYOLOEDetector`、`YOLOv10Detector` 等实现相同接口
>    - 可以在运行时切换检测算法
>
> 5. **命令路由模式**：`MqttHandler::commandHandlers_`
>    - 使用 `map<string, function>` 存储指令处理函数
>    - 根据 method 字段动态调用对应处理函数
