# 交叉编译配置说明

> ⚠️ **重要**: 本项目采用交叉编译方式，在 Docker 容器中编译 ARM64 程序

---

## 📁 新增文件

### 1. `cmake/toolchain-arm64.cmake`

**用途**: ARM64 交叉编译工具链配置

**关键配置**:

```cmake
set(CMAKE_SYSTEM_NAME Linux)
set(CMAKE_SYSTEM_PROCESSOR aarch64)
set(CMAKE_C_COMPILER aarch64-linux-gnu-gcc)
set(CMAKE_CXX_COMPILER aarch64-linux-gnu-g++)
```

### 2. `docs/Docker交叉编译指南.md`

**用途**: 完整的 Docker 交叉编译和部署文档

**包含内容**:

- Docker 环境配置
- 交叉编译步骤
- SE7 部署方法
- 常见问题解决
- 性能优化建议

### 3. `scripts/check_lib_arch.sh`

**用途**: 检查第三方库是否为 ARM64 架构

**使用方法**:

```bash
cd /path/to/ESDK_On_Sophon
bash scripts/check_lib_arch.sh
```

## 🔧 项目结构无需改变

### 为什么代码结构不需要改变？

交叉编译只是**编译方式**的改变，代码和项目结构**无需调整**，原因如下：

#### 1. ✅ C++代码是跨平台的

```cpp
// 这段代码在x86和ARM64上都一样
class Logger {
public:
    static Logger& getInstance();
    void info(const std::string& message);
};
```

**关键点**:

- C++标准代码在不同架构上语法完全相同
- 编译器会自动生成对应架构的机器码
- 不需要使用条件编译（`#ifdef ARM64`）

#### 2. ✅ CMake 会自动处理架构差异

```cmake
# CMake自动根据工具链选择正确的编译器
add_library(core STATIC Logger.cpp Config.cpp)

# 不需要写：
# if(ARM64)
#     add_library(core STATIC Logger.cpp Config.cpp)
# elseif(x86_64)
#     add_library(core STATIC Logger.cpp Config.cpp)
# endif()
```

**关键点**:

- CMake 通过`CMAKE_TOOLCHAIN_FILE`知道目标架构
- 自动选择正确的编译器和链接器
- 模块化的 CMakeLists.txt 无需修改

#### 3. ✅ 第三方库路径已经是 ARM64

```cmake
# third_party/CMakeLists.txt
set_target_properties(ThirdParty::ESDK PROPERTIES
    IMPORTED_LOCATION "${THIRD_PARTY_ROOT}/esdk/lib/aarch64/libedgesdk.so"
    #                                              ^^^^^^^ ARM64路径
)
```

**关键点**:

- 第三方库已经放在了`aarch64`目录
- CMake 会自动链接这些 ARM64 库
- 不需要区分 x86 和 ARM64 路径

## 🎯 交叉编译的影响范围

### ❌ 不需要改变的部分

1. **代码结构**:

   - include/和 src/的分离 ✅
   - 模块化设计 ✅
   - 头文件组织 ✅

2. **CMake 配置**:

   - 模块的 CMakeLists.txt ✅
   - target_link_libraries ✅
   - PUBLIC/PRIVATE 依赖 ✅

3. **设计模式**:
   - 单例模式 ✅
   - 工厂模式 ✅
   - 所有设计模式都与架构无关 ✅

### ✅ 需要注意的部分

1. **编译命令**:

```bash
# ❌ 错误（本地编译）
cmake ..

# ✅ 正确（交叉编译）
cmake .. -DCMAKE_TOOLCHAIN_FILE=../cmake/toolchain-arm64.cmake
```

2. **第三方库**:

   - 确保是 ARM64 版本 ⚠️
   - 使用`scripts/check_lib_arch.sh`检查 ✅

3. **测试运行**:
   - 编译后的程序不能在 Windows/x86 上运行 ⚠️
   - 必须部署到 SE7 上运行 ✅

## 🔍 如何验证交叉编译成功？

### 1. 检查可执行文件架构

```bash
# 在Docker容器中
cd build
file bin/ESDK_Sophon

# 期望输出：
# bin/ESDK_Sophon: ELF 64-bit LSB executable, ARM aarch64, version 1 (SYSV), ...

# 如果输出是 x86-64，说明没有使用交叉编译工具链
```

### 2. 检查依赖库架构

```bash
# 检查链接的库
readelf -d bin/ESDK_Sophon | grep NEEDED

# 使用ldd检查（需要QEMU环境）
qemu-aarch64-static -L /usr/aarch64-linux-gnu/ /usr/bin/ldd bin/ESDK_Sophon
```

### 3. 在 SE7 上测试运行

```bash
# 最终验证：在目标设备上运行
scp bin/ESDK_Sophon user@se7:/tmp/
ssh user@se7 "/tmp/ESDK_Sophon --version"
```

## 📊 交叉编译 vs 本地编译对比

| 特性           | 本地编译    | 交叉编译              |
| -------------- | ----------- | --------------------- |
| **编译环境**   | Windows x86 | Docker container      |
| **编译器**     | MSVC/MinGW  | aarch64-linux-gnu-gcc |
| **目标架构**   | x86_64      | ARM64                 |
| **运行环境**   | 编译机器    | SE7 微服务器          |
| **代码改动**   | 无需改动    | 无需改动 ✅           |
| **CMake 配置** | 标准配置    | 需要 toolchain 文件   |
| **第三方库**   | x86 版本    | ARM64 版本 ⚠️         |
| **编译产物**   | .exe / .dll | ELF / .so             |

## 🎓 面试要点

### 交叉编译相关

**Q1: 为什么需要交叉编译？**

A: 嵌入式设备（如 SE7）资源有限，不适合直接编译大型项目。
使用强大的 x86 开发机编译，速度快、环境统一。

**Q2: 交叉编译会影响代码吗？**

A: 标准的 C++代码不需要改动。但要注意：

- 字节序（大端/小端）
- 指针大小（32 位/64 位）
- 架构特定的优化（SIMD 指令等）

**Q3: 如何确保链接到正确的库？**

A: 1. 使用 CMAKE_TOOLCHAIN_FILE 指定工具链 2. 设置 CMAKE_FIND_ROOT_PATH_MODE_LIBRARY 为 ONLY 3. 验证库文件架构（file 命令）

**Q4: 交叉编译的程序能在开发机上测试吗？**

A: 不能直接运行，但可以：

- 使用 QEMU 模拟 ARM64 环境
- 在实际目标设备上测试（推荐）

## 📝 快速上手步骤

### 第一次编译

```bash
# 1. 进入Docker容器
docker exec -it stream_lzy /bin/bash

# 2. 进入项目目录（容器内路径）
cd /workspace

# 3. 检查第三方库架构
bash scripts/check_lib_arch.sh

# 3. 创建构建目录
mkdir -p build && cd build

# 4. 配置（使用交叉编译工具链）
cmake .. \
  -DCMAKE_TOOLCHAIN_FILE=../cmake/toolchain-arm64.cmake \
  -DCMAKE_BUILD_TYPE=Release

# 5. 编译
cmake --build . --parallel 8

# 6. 验证架构
file bin/ESDK_Sophon

# 7. 部署到SE7
scp bin/ESDK_Sophon user@se7:/opt/esdk/
```

### 日常开发

```bash
# 修改代码后，只需重新编译
cd build
cmake --build . --parallel 8

# 重新部署
scp bin/ESDK_Sophon user@se7:/opt/esdk/
```

## 🚨 常见错误

### 错误 1: 忘记使用 toolchain 文件

```bash
# ❌ 错误
cmake ..

# 症状：编译成功，但在SE7上无法运行
# file bin/ESDK_Sophon 显示 x86-64

# ✅ 正确
cmake .. -DCMAKE_TOOLCHAIN_FILE=../cmake/toolchain-arm64.cmake
```

### 错误 2: 使用了 x86 版本的第三方库

```bash
# 症状：链接时找不到库，或运行时Segmentation Fault

# 解决：检查并替换为ARM64版本
bash scripts/check_lib_arch.sh
```

### 错误 3: 在 Windows 上运行交叉编译的程序

```bash
# ❌ 无法运行
./build/bin/ESDK_Sophon.exe

# ✅ 必须在SE7上运行
ssh user@se7 "/opt/esdk/ESDK_Sophon"
```
