## 🐛 常见问题排查

### 问题 1：程序卡住不动

**症状**：运行 `./test_day6_integration` 后没有任何输出

**原因**：Config-Logger 循环依赖导致死锁

**解决方案**：

- ✅ 已修复：移除了 `config.load()` 调用
- 重新编译：`cd /workspace/build && make -j8`

---

### 问题 2：RTMP 连接失败

**症状**：

```
[ERROR] 打开 RTMP 连接失败: Connection refused
```

**可能原因**：

1. 网络不通
2. RTMP 服务器地址错误
3. 服务器不可访问

**排查步骤**：

```bash
# 1. 检查网络连接
ping 27.223.85.130

# 2. 检查端口是否可达
nc -zv 27.223.85.130 3519

# 3. 检查 URL 是否正确
cat /data/Edge-SDK/config/config.json | grep rtmp
```

---

### 问题 3：推流成功但播放器看不到画面

**可能原因**：

1. RTMP URL 不匹配（推流和播放使用的 URL 不同）
2. 服务器端配置问题
3. 网络延迟过高

**解决方案**：

- 确保推流和播放使用**完全相同**的 URL
- 检查服务器日志
- 减少网络延迟

---

### 问题 4：帧率不稳定

**症状**：

```
平均帧率: 15.2 FPS  （期望 30 FPS）
```

**可能原因**：

1. 网络带宽不足
2. CPU 性能不足
3. 编码器参数不当

**优化方案**：

- 降低分辨率（1920x1080 → 1280x720）
- 降低帧率（30 fps → 25 fps）
- 降低码率

## 🎓 知识点总结

### 1. RTMP 推流原理

**不需要本地 RTMP 服务器**！

- FFmpeg 的 `libavformat` 内置 RTMP 客户端
- 直接连接到远程 RTMP 服务器
- 类似于 GStreamer 的 `rtmpsink` 插件

**工作流程**：

```
本地程序 (SE7)
  ↓ H.264 数据
FFmpeg RTMP Client
  ↓ RTMP 协议
远程 RTMP 服务器 (27.223.85.130:3519)
  ↓ RTMP 协议
播放器 (VLC/手机)
```

### 2. Config-Logger 循环依赖问题

**问题**：

```
Config::load() → Logger::getInstance()
Logger::Impl() → Config::getInstance() → 死锁！
```

**解决方案**：

- 不在测试代码中调用 `config.load()`
- 让 `Logger` 使用默认配置
- 在 `Application` 层面统一管理配置加载

### 3. H.264 NAL 单元类型

| NAL Type | 名称   | 说明               |
| -------- | ------ | ------------------ |
| 1        | P 帧   | 预测帧（参考帧）   |
| 5        | IDR 帧 | 关键帧（独立解码） |
| 7        | SPS    | 序列参数集         |
| 8        | PPS    | 图像参数集         |

**识别方法**：

```cpp
uint8_t nalType = h264Data[4] & 0x1F;  // 取低 5 位
if (nalType == 5) {
    // 这是 I 帧（关键帧）
    packet.flags |= AV_PKT_FLAG_KEY;
}
```
